# Preview frame-rate and crash repair

The user tried the initial preview and reported extremely low FPS and a crash. A live CPU sample found nearly all main-thread time in repeated full layout graph synchronization inside each Pane::AnimateSelf. Native pane animation now processes only that pane, as original NW4R does; the existing later matrix/follow phase publishes global transforms. No Game callbacks, layout actors or timestep updates were removed.

Collision queries stored scratch vectors in caller Game heaps. The original preview failed at tick412 requesting1664 bytes with1232 bytes free. Native sphere/point/line traversal and retained TLS results now allocate on the host, and actual original triangle filters regain caller Game routing. Group-checker registry buckets also remain host-owned after original Game children retire.

Measurements from the actual disc scene (debug timing enabled): original O0 preview averaged0.137 presents/second between its3 presents, simulation11.4ticks/second, then aborted at shutdown. Corrected pane/allocation O0 build averaged19.16FPS, simulation60.33ticks/second, but still hit the group registry shutdown fault. Corrected optimized debug build averaged53.97FPS and60.04simulationticks/second over1200ticks/20.99wallseconds, then exited0. Different run lengths reflect the original runaway catch-up cost; results are bounded local measurements, not a full-game benchmark. Exact executable hashes/commands are in results.json.

New opt-in root Xmake option optimize_debug=y enables -O2 for debug Game and Aurora targets while retaining symbols, SMGPC_DEBUG_BUILD, assertions and existing per-file FP rules. No fast-math/NDEBUG addition. Configure with mode.debug and explicitly preserve the Homebrew LLVM23 cc/cxx/ld/sh/mm/mxx paths: Xmake reconfiguration otherwise reselects the system compiler. Final optimized-flags.json verifies LLVM23/-O2/debug and Binder's -ffp-contract=off. An initial system-compiler build was interrupted before link; it is not the measured artifact.

Four relevant optimized fixtures built and ran0: original layout phase/render/heap lifetime, stage collision repeated hit/miss queries, bounded strike TLS lifetime, and scene-name/group registry lifetime. Full older line-collision fixture retains an unrelated water scene-owner setup failure; the exact new bounded group is selected explicitly.

This is recorded for reference-first recovery in ../mario-stage-in-transition-audit-20260910; it is not changed or claimed fixed in this preview.
