# Drain native mapping callbacks before graphics teardown, 2026-09-07

One of six earlier effect processes completed all original effect, heap and image assertions, then aborted on a Metal completion thread inside Dawn BufferBase::MapAsyncEvent::Complete. Source inspection found three native owners that discarded MapAsync futures. Their shutdown paths reset slot state and released readback/staging buffers before outstanding callbacks were known to have returned. Waiting for CPU render work alone does not wait for asynchronous GPU callbacks. Depth snapshot and sequence IDs also reset, permitting a stale callback to match a reused slot after a later initialization.

The shared webgpu/map_future.hpp helper uses the live WebGPU instance's WaitAny to retire callback completion, not merely a slot flag set inside the callback. Its native MapFutureTracker retains every map future, retires completed futures during ordinary use, and drains remaining callbacks after map producers have stopped. It swaps pending work out under its metadata mutex, then performs every callback wait outside that mutex and the owners' slot mutexes. Tracker metadata always allocates under Aurora HostAllocationScope.

Frame staging maps are drained after render_worker shutdown and before staging-buffer release, slot-pool reset or mapping-state reset. Depth reset drains all map callbacks before taking its slot mutex or recycling slot/snapshot IDs. The existing shutdown order keeps buffers, device and instance alive throughout. GPU profiler slots retain their own future; normal reuse waits for actual callback completion, and profiler shutdown drains every slot before buffer/state teardown. No sleep delay, fake completion flag or abandoned callback is substituted.

LLVM23 compiles all three changed translation units. The profiler has separate successful syntax checks with exact -DTRACY_ENABLE and -UTRACY_ENABLE; the initial audit confused TRACY_ENABLE_CALLSTACK with TRACY_ENABLE, and the corrected manifests explicitly show both variants. TimestampQuery is not enabled in this runtime configuration, so profiler runtime behavior is not claimed as tested.

It requires actual READY depth snapshots, reads their GPU-derived Z values, and checks independent far, near and copy-clear boundaries. It built and passed5 consecutive native Metal runs, including clean shutdown. Compatibility adapter selection still enabled CoreFeaturesAndLimits on the Apple M5 Max, so this test exercises actual depth MapAsync, not metadata-only requests or a disabled path.
