## Aurora SDK lifecycle

OSExecution now implements real OS-created native threads with their supplied OSThread identity, initial suspended state, priority fields, stack metadata, per-thread specific values, normal return/exit, SDK detach/join behavior, suspension counts, and cancellation. OSReceiveMessage/OSSendMessage keep their existing actual intrusive queues and blocking waits. Resume and wake respect suspension; cancelling a waiting worker removes it from its queue and waits for native thread completion before returning, so the original wrapper can release thread/stack/queue memory safely. Internally joining SDK-detached threads preserves native resource ownership; detach still makes SDK OSJoinThread return false.

The existing emulated-CPU gate now covers the whole guest worker callback. Host entry points use `aurora::os::GuestThreadExecutionScope` from `aurora/guest_thread.hpp`; SDK blocking waits and explicit yields release the gate while retaining scope and saved interrupt state. This preserves the original executor's unprotected fields and post-message completion writes without concurrent Game accesses. Parent owns wrapping actual process construction/update/teardown. It is cooperative execution at SDK boundaries, not host signal masking or asynchronous interruption of arbitrary C++ code. A worker that never reaches a wait/yield must return before another guest caller obtains the CPU gate. Adopted host threads cannot be cancelled through this SDK API.

Worker metadata and std::thread allocations are host-routed. An OS-created callback inherits the creator's callback-allocation classification; it uses the existing shared Game heap selection under the serialized CPU scope. Native workers receive their own identity rather than pretending to be the main thread. An unhandled worker exception is fail-loud; the SDK has no invented cross-thread exception/result protocol.

The four newly imported src/revolution/os/{OSMessage,OSThread,OSContext,OSTime}.h files forward to canonical Aurora headers so Wii-size records cannot shadow native pointer-width layouts. Depth owns JKRUnitHeap and MEM2 boundaries; initialization owns the NAND worker. No global build, isolated native compile, or new tests were run at the parent's request. The parent must perform the combined build and linked lifecycle verification; this source checkpoint alone does not claim startup is working.
