# Original Scene native retirement boundary

The actual derived Scene now retires before native stage services, and native stage services retire before the original Scene base deletes its actual SceneObjHolder and list executor. The hook and native constructor exception cleanup live in SceneLifetimeCompat.cpp; Game/Scene/Scene.cpp is restored byte-identical to the reference and excluded from the native target. StageHostScene borrows its extracted initialization service. SceneLifecycleService retains that service and one shared original Game allocation domain through the entire Scene/base destructor and operator delete. SceneObjHolderBinding accepts that actual domain instead of creating a second hidden heap.

Stage initialization publishes the new typed Scene execution binding after constructing the actual holder and executor. During retirement, registered actor roots leave their original queues while their owners still exist; prepare_retirement tombstones remaining execution memberships, then SceneObjHolderBinding destroys its actual objects, then the execution binding retires. This integrates with the concurrent original execution-owner cohort; aggregate host execution still awaits the full GameScene activation.

SceneLifetimeBindingTests.cpp compiled, linked and ran successfully with the actual native Scene, original SceneObjHolder and NerveExecutor/Spine owners. It checks derived/base callback order, callback self-removal, duplicate binding rejection, out-of-order cancellation, and32 repeated allocations returning the entire Game domain to the original JKR root. The fixture does not instantiate GameScene or exercise its gameplay nerves. validate.py records exact compile/link commands; lifetime-test-result.json and run.log are the isolated proof. This is not a full archive/main build or a playable jumping/camera demo.
