In retail, `CameraManGame::calc` calls `selectCameraChunk` every calculation; normal selection takes the category's CubeCamera first, then a valid ground polygon camera ID with the surface's zone/host name, otherwise the preceding/default chunk (`decomp/src/Game/Camera/CameraManGame.cpp:53`, `:183`, `:560`, `:629`). The original reset/no-reset and old-chunk end-interpolation rules are consequently absent on area crossings (`:257`, `:307`). Water and other mode selection are absent too. `end_start_position_camera` only changes flags (`RuntimeServices.cpp:3228`), so it cannot exit the StartInfo controller. Retail also automatically ends start mode after the original time/movement test (`decomp/src/Game/Camera/CameraDirector.cpp:319`); no equivalent test exists in this service. **Next:** retain the real parameter catalog and original CameraHolder/CameraManGame selection graph, with typed host ownership; validate overlapping CubeCamera priority, grounded group IDs, leaving areas, original no-reset combinations, and start-to-normal transition. Do not add a Gateway camera switch.

2. **P1 — The normal stage lifecycle has no player-target attachment.** `StageHostScene::init_stage_start_camera` creates the camera owner but never binds a target (`src/scene/StageHostScene.cpp:638`). `set_owned_stage_camera` leaves its optional target and player pointer empty; `update_authored_game_camera` then returns before calculation. The only production caller of `set_game_camera_target_player` is the showcase (`src/showcase/Showcase.cpp:775`). The only production construction of `CameraTargetPlayer` is likewise that showcase adapter. Thus a future real Mario attachment to the regular StageHost route alone will still leave the start pose static. StageHost currently reports the absence of its complete player owner explicitly (`StageHostScene.cpp:308`); this is a missing general integration boundary, not evidence of live Mario camera failure in the showcase. **Next:** attach/detach the original target with the real scene player owner and bind the camera generation there, including actor replacement and scene retirement. Coordinate with the current Mario constructor/owner restoration.

3. **P1 — Event priority and shared target lifetime are still reduced to one slot.** CameraParam decodes `evpriority` (`src/camera/CameraParam.cpp:178`), but `EventCameraRuntime` has one `_pending` and `_active` and never reads that field (`src/camera/EventCamera.cpp:258`, `:342`, `:420`; `EventCamera.hpp:154`). A second request overwrites the first regardless of priority, and ending it cannot resume an independently retained lower-priority event. Retail requests a per-priority pending entry and applies the first populated priority (`decomp/src/Game/Camera/CameraManEvent.cpp:47`, `:175`, `:204`, `:348`). There are two additional concrete target mismatches: a first no-target event throws even when the game already has a valid player target (`EventCamera.cpp:283`), and `end` does not reset `_last_target` to the player (`:365`). Retail no-target requests retain the shared CameraTargetHolder; when the event FIFO empties it explicitly selects the player (`decomp/src/Game/Util/CameraUtil.cpp:661`, `:705`; `CameraManEvent.cpp:53`). A later no-target event can therefore inherit an old actor/matrix target or fail its retired-object validation. **Next:** restore the original priority slots and one director-selected target lifetime shared by game/event phases. Preserve the already implemented same-chunk cursor retention, pending promotion, matrix invalidations, manager pose seeding, and finish interpolation.
