# Next removal: TalkDirectorLifetime first

**Choose TalkDirectorLifetime.cpp/.hpp for the next bounded batch.** It owns no allocations: it only remembers one registered TalkDirector and scrubs borrowed controller/actor identities. The actual TalkDirector, TalkState, TalkBalloon, and TalkMessageCtrl implementations already exist. LayoutActor now owns its native layout teardown, so this removal does not require another rendering or resource service.

## Concrete implementation closure

1. Put native borrower retirement on the actual `Game/NPC/TalkDirector` class: a retiring flag, a `beginNativeRetirement()` operation, and `releaseNativeReference(const NameObj*)`. Preserve the current policy: deleting a participant while its conversation or balloon is active terminates unless scene retirement has begun. Do not synthesize `termTalk()` or camera/demo transitions during deletion.
2. Preserve the exact scrubbing set from the provider: `mMsgControls`, `mMsgCtrl/_3C/_40/_44`, all five TalkState controller references, four short balloons, event/info/sign/icon balloons, and the state holder's short balloon. Match both controller identity and `controller->mHostActor`. Balloon references are borrowed; skip already-retired NameObj identities as the current implementation does. Make incomplete initialization safe by initializing the director's holder/peek pointers and guarding absent holders.
3. `ActorRuntimeRegistry::release_name_obj_runtime_state` already scans actual registered DemoDirector, DemoExecutor, groups and arrays. Add the actual TalkDirector to that existing loop, then remove its call to `current_talk_director_lifetime()`. This removes captured generation/TLS indirection without introducing another owner registry. The existing scan must continue seeing controller and actor deletion before erasing their NameObj identity.
4. In `SceneObjHolderBinding::prepare_retirement`, mark the actual TalkDirector, if constructed, before scene unpublication and deletion. Remove `_talk_director_lifetime`, its constructor allocation, init capture, current-accessor/friend declarations, and the two compat files. Keep the original TalkDirector factory and initialization path.

Minimal source set: `Game/NPC/TalkDirector.cpp/.hpp`, `compat/ActorRuntimeRegistry.cpp`, `compat/SceneObjHolderCompat.cpp`, `scene/SceneObjHolderRuntime.hpp`, and the two deleted provider files. No donor gameplay body needs replacement: TalkDirector is already complete and the required change is native borrowed-reference retirement.

**Allocation ownership boundary:** TalkBalloonHolder and TalkStateHolder allocate Game-heap helpers; the scene's NameObj graph owns their balloons, IconAButton objects and controllers. Do not add blanket deletion of those NameObj children from the director. The present lifetime provider explicitly leaves helper storage to the scene arena. If pursuing full independent director destruction in the same batch, that is a larger closure: give TalkBalloonHolder its pointer-array cleanup, TalkStateHolder its non-NameObj state cleanup (typed/virtual destruction matters), and TalkPeekZ callback retirement; first establish which registered children the scene still owns. These changes are not required to remove the current borrower-only provider and should not be hidden in a copied catch-all.

Existing evidence to reuse, without adding a fixture: `tests/TalkRealOrAbsentTests.cpp` already runs the actual original process, registers two controls for one actor, exercises authored Gateway message nodes/balloon text, and observes retirement. No new synthetic standalone director owner is needed.

## Why the other two are larger

**MarioAnimatorLifetime.cpp/.hpp is the next candidate after Talk.** Its construction scope captures the lower/upper XanimePlayer and XanimeCore allocation identities, resource hash/group tables and callbacks; ModelManager retains that graph plus the ResourceHolder token and heap domain. Upper and lower cores share joints/transforms, own separate tracks, and lazily allocate simple groups. The provider also restores the previous ModelManager player, `j3dSys`, and the original recursive mutex count on constructor failure. Complete owner migration must cover MarioAnimator, XanimeResourceTable, XanimePlayer, XanimeCore, and the actual ModelManager dependency path together; Mario's runtime player/model mutations mean simply deleting current public pointers is unsafe. Preserve resource tokens until model/animation teardown and delete the animator only after cores that borrow its matrices. This is a coherent animation ownership batch, not a local destructor insertion.

**EffectSystemOwnership.cpp/.hpp is widest.** It combines an alternate RuntimeContext/8-MiB heap bootstrap, actual scene EffectSystem construction/entry, two global actor/layout keeper maps, and callback retirement. Removing it coherently needs actual `EffectSystem`, `EffectKeeper`, `PaneEffectKeeper`, `MultiEmitter`, `SyncBckEffectChecker`, `AutoEffectGroupHolder/AutoEffectGroup`, emitter pool and calc/draw executor ownership. Preserve scans of `mLastNonzeroUserWork`: replaced one-shot emitters can remain alive after unlinking from their SingleEmitter and still borrow keeper callbacks. Scene adapters/functors must retire before their calc/draw executors, keepers before emitter-manager shutdown, and the process ParticleResourceHolder must outlive the whole scene. Existing LiveActor and newly restored LayoutActor init/release methods currently call this provider, so both classes need coordinated canonical integration. Removing only the bootstrap would leave most of the compat ownership surface intact.

This recommendation is based on source inspection only. No code changes, builds or tests were performed for this audit.
