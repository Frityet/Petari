# Independent clipping review — 2026-09-07

Read-only review by the camera/area agent; the backend owner handles production changes and GPU validation. These findings refer to the first implementation reviewed, not a claim that they remain unfixed. No source edits or GPU runs were made by the reviewer.

1. **Viewport top must invalidate uniforms.** New `viewport_to_target.w` depends on `g_gxState.renderViewport.top`, but the existing `set_render_viewport` comparison included only left/width/height. A second clip-disabled draw after a purely vertical viewport move could reuse the first draw's transform, while its recorded viewport restoration used the new top. Reported to the owner; owner confirmed the top comparison and a same-stream two-draw regression are now added. Relevant sources: `aurora/lib/gx/gx.cpp::set_render_viewport`, `shader_info.cpp::fill_uniform`.

2. **The existing indexed extension also needs the triangle storage path.** `GX_AURORA_DRAW_INDEXED` directly called `push_gx_draw` without the triangle storage range. With clipping disabled its pipeline still selected the new instanced-triangle shader, but `triangleIndexStart` stayed `UINT32_MAX`, and DrawIndexed supplied original vertex indices where the shader expects vertex IDs 0–2. This extension is emitted by `GXBeginIndexed` and the display-list optimizer, so ordinary FIFO triangle coverage does not validate it. Reported to the owner: reuse the existing native-endian index span as storage and record the same instanced triangle draw, preserving those indices. Relevant source: `aurora/lib/gx/command_processor.cpp::handle_aurora`, `GX_AURORA_DRAW_INDEXED` branch.

3. **Offscreen target transitions need explicit viewport/cache reconciliation.** The new uniform also depends on current render-target dimensions, while `uniformValid` only considers DirtyUniform. `gfx::begin_offscreen`/`end_offscreen` change attachments and recorder `cachedViewport` directly, without clearing the GX uniform cache or updating `g_gxState.renderViewport`. An in-frame transition with the same sample count can therefore reuse the previous target's transform. In addition, a clip-disabled draw restores the GX-state viewport while the offscreen recorder may have installed its own default viewport. Reported as a concrete cache/ownership path for correction and a target-transition regression. Next-frame resize is a different path and already clears the uniform range.

The reviewed main triangle path otherwise preserves host FIFO allocation scope, copied frame-storage index lifetime, original strip/fan/quad triangle winding, raw indexed position and PN-matrix fetches, immutable per-draw payloads, and disabled-mode merge suppression. Viewport mapping uses the correct top-origin Y offset; full attachment clipping bounds discard only unobservable pixels outside the attachment. Trivial rejection uses the independently ANDed original six outcodes, including `w*z > 0`, before the negative-W clipping decision. Projection/depth conversion and explicit clip planes are formed before authored depth scaling. The tagged Geometry/ClippingViewport union retains the inline command payload size.

The negative-W and extreme guardband behavior is explicitly a Dolphin-software-derived approximation with the same documented unknown hardware condition. No independent hardware parity or complete clipping correctness is asserted here. Backend test logs and the owner's final note should identify the final status of the three actionable paths above.

## Source re-review of the corrections

All three corrections were subsequently inspected in the saved working tree: `set_render_viewport` includes top in DirtyUniform invalidation; `GX_AURORA_DRAW_INDEXED` uploads its actual index span to storage and records the common instanced branch when clipping is disabled; offscreen start/restore both reconcile `g_gxState.renderViewport` and unconditionally invalidate the target-dependent uniform. No further actionable issue was found in those three corrections. Runtime validation remains with the backend owner; this re-review itself did not run GPU commands.
