# Read-only build/performance audit

Current `.xmake/macosx/arm64/xmake.conf` selects debug, Apple arm64, Homebrew LLVM. Actual `compile_commands.json` entries for Mario/MarioActor, native compatibility and LayoutRuntime, Showcase, Aurora GX and WebGPU all contain `-g -O0`, `SMGPC_DEBUG_BUILD`, and no `NDEBUG` or fast-math flag. This is an unoptimized CPU build; it is not evidence by itself that optimization explains the measured stall.

Dawn is a prebuilt static `v20260807.225922` darwin-arm64 package; its installed manifest says release/debug=false. `packages/d/dawn-build/xmake.lua` only downloads and copies the prebuilt tree, so exact upstream optimizer/assertion flags cannot be recovered from the local Xmake manifest.

`aurora/lib/webgpu/gpu.cpp` explicitly disables backend validation. API validation and shader robustness remain enabled in this debug build: the skip_validation and disable_robustness toggles are guarded by NDEBUG. Tracy's enable macro is absent from actual compile arguments; similarly named CALLSTACK/FIBERS macros alone do not enable its instrumentation. Gameplay timing logs require `SMGPC_DEBUG_SIMULATION_TIMING`, and the packaged launcher does not set it. J3D packet traces are requested only by smoke mode in Showcase. The normal launcher requests gateway plus resolution and disc path, without smoke.

Root Xmake registers debug/release only and adds NDEBUG for every non-debug mode. Xmake's built-in profile rule also adds NDEBUG and -pg. Therefore switching to release/releasedbg/profile would not preserve the requested assertions and debug surfaces. The safest future opt-in is to retain mode.debug, set target optimization to `faster` (-O2) with debug symbols across both root and Aurora targets, preserve existing per-file floating-point contraction controls, and add no fast-math flags. Xmake's debug rule respects an explicitly supplied optimization value. This option does not exist in the current project; no configuration or build scripts were changed during this audit.
