# One Aurora compatibility shim provider

The expanded actual-provider audit found five duplicate strong symbols because executables compiled `aurora/lib/compat.cpp` directly while also depending on `aurora-base`, which already owns it. Removed that source entry from `src/app/xmake.lua`, `src/debug/xmake.lua`, and `tests/xmake.lua`. The Aurora shim source and sole Aurora base source definition are unchanged.

`affected-targets.json` enumerates 176 actual configured targets: main, the title probe, and 174 tests, including the 24 targets generated by two fixture tables. `check_graph.lua` resolves the configured Xmake graph and verifies every affected target retains the transitive `aurora-base` dependency, has no direct shim source or object, and contains no old direct object in its direct link command. It also verifies that Aurora base is the only configured target compiling this source. The raw dependency report is compressed as `configured-shim-dependencies.json.gz`; the individual target link commands describe their direct inputs, while `dependencies` records the transitive static-library ownership. Existing old `.o` files on disk are harmless: none remains in these configured object lists.

The five requested targets explicitly relinked successfully: main, original-process player owner, original actor utility, original placement coverage, and original scene execution owner. Build logs and hashes are listed by `notes/compat-original-provider-cleanup-20260919/single-shim-build-results.json`. No 176-target build/runtime claim is made; all 176 were checked in the source/dependency graph, and these five were linked.

All four test executables passed (`run-results.json`). The player test completed 360 ordinary original frames, passed the retained state/walk/camera/PlayerUtil checks, and verified normal original player retirement. PID 9405 exited 0 and was reaped; the other three pure checks likewise exited 0. This does not erase the separately recorded missing-process-owner failures in older standalone resource/render fixtures.

The final main SHA256 remains `6fd4824a3217cb18bb7f6533936202a4854c6475a7fbef895176a2ba91ffbb43` despite its actual relink and bundle regeneration. `artifact-symbols.json` verifies that none of the five shim symbols is present in the dead-stripped macOS executable, while each has a single strong definition in `libaurora-base.a:compat.cpp.o`. Removing the unused direct object therefore leaves this executable byte-identical. Aurora base remains available for platforms or targets that require those symbols.

Build and GPU ownership were released to the runtime-smoke agent after these checks. No Game source, shim body, staging, or commit was changed by this follow-up.
