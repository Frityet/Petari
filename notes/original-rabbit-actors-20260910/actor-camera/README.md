# Original ActorCameraUtil and native camera resources

The first real rabbit initialization reached createActorCameraInfo and failed because native ActorCameraUtil still delegated allocation to the old EventCameraRuntime catalog. The current scene already owns a complete CameraDirector. The entire native ActorCameraUtil CPP and paired header are now exact current decomp copies: camera information uses ordinary original new on the current Game heap, and declaration/start/end/query paths use original CameraUtil, which already forwards to the actual CameraDirector.

This removes actor-level event-name/presentation reimplementation, host catalog allocation requirements and actor-specific resource fallback. Original names, bounded buffers, ID checks, target selection, programmable operations, both animation initialization overloads and rumble helpers are retained. No new reference recovery was needed.

Original initAnimCamera passes ResourceHolder's `.canm` resource directly into CameraAnim, whose original accessors read native scalar records. Previously the actor helper privately decoded those bytes. That architecture conversion now lives at the shared ResourceArchiveOwner typed-file boundary alongside existing BTI handling: decode via existing CameraAnimation::from_bytes, retain NativeCameraAnimationData with the archive owner, and publish the native block through the actual JKR file cache before ResourceHolder enumeration. Thus original file-table lookups and original loadResourceFromArc share the same retained native bytes. CANM/CKAN algorithms remain the original CameraAnim implementation; this change only relocates endian decoding and storage lifetime. The original `.canm` suffix is confirmed by retail ActorCameraUtil.s string1156.

Added the exact missing loadResourceFromArc declaration to ObjUtil.hpp; its original provider already exists. Both affected native TUs compile successfully. The first actor-camera compile identified that missing declaration; only that failed TU was retried after correction. No broad tests or Wii recompilation were performed, since Game source is an exact copy. Parent owns the next combined build and short live smoke.

The unused legacy EventCameraRuntime allocation API is no longer reached by Game. Existing ActorEventCameraTests that assert its native allocation counter are stale and are not claimed to pass. A broader legacy camera-service cleanup is separate from this runtime unblock.
