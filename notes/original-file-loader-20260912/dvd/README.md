# DVD value descriptors and native operation ownership

The original FileLoader component passed its real queue ordering, duplicate suppression, streamed file-byte comparison, complete archive catalog comparison and original completion-state checks. It then failed exact heap restoration: the actual singleton and volume list were restored, but 136 bytes remained allocated. The diagnostic heap dump contained the expected persistent 64-byte FileRipper read buffer plus two unexpected 16-byte allocations. See `../shared-retirement-diagnostic-run.log` and its JSON receipt.

Aurora's DVDOpen path allocated one polymorphic CommandDataNod per opened descriptor, stored it in the original caller-owned `DVDCommandBlock::userData`, and freed it only in DVDClose. The original FileRipper opens stack DVDFileInfo values and never closes them. This is consistent with the SDK contract: `decomp/src/RVL_SDK/dvd/dvdfs.c:162` sets only file-position/length/callback/state values, and its DVDClose at line 197 cancels outstanding work without freeing an allocated descriptor resource. The native 16-byte vptr/handle objects therefore accounted for the two leaked guest allocations. No Game FileRipper close calls were added.

The native SDK now retains only a POD catalog generation and file entry number in DVDFileInfo. A submitted DVDCommandBlock copies that identity so its operation is explicit; raw absolute DVD commands use the disc identity and never inspect userData. DVDOpen preserves caller-owned userData and performs no handle allocation. The worker opens its own Nod or overlay handle for each actual read/seek operation, stores it in a stack optional with a destructor, and closes it before publishing completion or entering the client callback. The same descriptor can therefore be reused from a callback or disappear after a completed synchronous read without leaving an owning native object behind.

The descriptor and operation additions widen native SDK structures, which is an architecture change, not a retail-layout claim. The original startAddr compatibility behavior is unchanged by this bounded ownership fix. Disc close/reopen and catalog replacement advance a guarded generation. Old descriptors fail rather than resolving to a new disc or replacement overlay with a reused entry number. Already executing overlay commands keep the callback table used to open their handle, including its matching close function. Overlay open callbacks run outside the FST mutex and can use ordinary DVD lookup APIs.

Native worker queue/container and FST allocations escape guest global-new routing. Those escapes do not wrap canceled/client callback execution and do not change the existing callback scheduling policy. Current read/cancel/close callback delivery remains a separate compatibility concern; this change does not claim a new guest interrupt callback scheduler.

Eight regressions were added to the existing Aurora DVD suite: raw absolute commands preserve userData, repeated stack-descriptor reads without close release every handle, callbacks close/reopen the same descriptor, queued cancellation never acquires a handle, close waits for an active read and its callback, disc replacement invalidates old descriptors, catalog replacement invalidates old descriptors, and replacement drains a blocked old open/read before the caller destroys its payload. Overlay counters verify exact acquired/released handle counts and that no handle remains active. The suite accepts SMGPC_REAL_DISC at runtime while retaining its compile-time disc option.

Direct native compilation passes for both implementation files and the test TU. `native-compile.json`, `tests-compile.json` and `source-manifest.json` record exact commands and sources. The coordinator rebuilt the original FileLoader target and its real-disc invocation passed all three actual worker/archive teardown cycles with exact original heap restoration: `../shared-dvd-identity-build.json`, `../shared-dvd-identity-run.json`. The final standalone DVD suite now passes all 46 tests; independent source review found the overlay replacement race and the final revision includes its operation-lifetime barrier. This component pass does not establish full GameSystem startup or gameplay.

The first standalone real-disc DVD suite run passed 44 of 45 cases; its only failure compared the raw disc header reserved padding with the normalized SDK DVDID padding. That test now compares only the ten defined header fields. Source review also identified a new gap between copying an overlay payload pointer and entering its open callback. A catalog lifetime lock now covers each operation through handle close; replacement acquires exclusive ownership before changing either catalog entries or callback tables. Both lock acquisitions release any held guest CPU gate through GuestThreadWaitScope. Lookup callbacks remain reentrant. Replacement from inside its own open/read/seek/close callback is rejected before recursive writer deadlock and is documented as an API precondition. The added blocked-open/read test checks replacement waiting, old-payload retirement, and guest CPU progress. The final standalone suite passes 46/46 tests in `../dvd-barrier-run.json` and the final original FileLoader rerun passes all three exact-heap-return cycles in `../file-loader-final-run.json`.

Final executable identities: DVD suite `22f57376cbf8b7fca367becc0f23499aa88cc53947c668ef62a4ffdf5acf39f8`; original FileLoader fixture `8a606fa9a233e4319bffe3d5d932ab5dbde30f557842a49dda423c888ac0bc19`. Eight new C++ tests cover the raw-command callback-data boundary and the seven descriptor/lifetime scenarios; the blocked replacement test runs both open and read phases and actually destroys the replaced payload after the barrier returns. Existing unrelated DVD tests remain part of the 46-test run.

A second independent read-only review of the final delta found no additional material descriptor/handle lifetime flaw: optional handles close before completion, the catalog lifetime scope covers all overlay operations, replacement drains before payload retirement, and generations reject stale descriptors. Broader DVD startup publication/query concurrency and guest callback blocking remain outside this validated delta.
