# Original file request and archive ownership

Imported the complete original FileRipper, FileLoader, FileLoaderThread, FileHolder, ArchiveHolder and FileUtil translation units. Five native copies are byte-identical to the current reference. FileRipper differs only at its raw Yaz0 expanded-length read, which uses the existing Aurora big-endian primitive on the host. The original compiler and native compiler both accept all six translation units. The isolated original FileLoader component now passes its real-disc runtime checks and three complete worker/archive retirement cycles; this is not full GameSystem startup or gameplay evidence.

Two reference-first portability corrections accompany the import: FileLoader's integer request count uses `0` instead of the invalid integer assignment from `nullptr`, and FileRipper's stack alignment uses the SDK's canonical `ROUND_UP_PTR` macro instead of truncating a host pointer to `u32`. Aurora's macro preserves native pointer width. The original compiler matches the complete retail text at 99.97793% for FileRipper, 99.31921% for FileLoader, 99.77778% for FileLoaderThread, 100% for FileHolder/ArchiveHolder and 99.96037% for FileUtil.

The SDK's missing JKRMemArchive::fetchResource_subroutine is supplied at the existing native archive boundary, following its original switch and destination clipping. Compressed resources use the actual JKRDecomp worker for both Yay0 and Yaz0; uncompressed resources copy the clipped source length. Native sizes use explicit Wii-width u32. The unsupported compression panic currently reaches OSPanic instead of the not-yet-imported JUTException console path. No decoder substitution or completed-request state is added.

FileLoader's authoritative state consists of its original 320 request records, original OSThreadWrapper worker, FileHolder's heap-allocated file entries and buffers, and ArchiveHolder's actual JKRMemArchive objects. The worker publishes completion through the original per-file OS message queue. Native queue and scheduling support remains shared Aurora infrastructure.

Full FileUtil activation is deliberately held, with a temporary build exclusion owned by the root agent. Its imported original methods replace the old synchronous native map, fixed Korean path selection and no-op receive-all behavior, but its archive identities must also replace the competing archive service throughout the resource consumers. Merely switching MR wrappers would leave the new ArchiveHolder invisible to ResourceHolderService and would break ownership.

The intended boundary is one actual Game archive graph. ArchiveMountService may remain an explicitly called native archive reader for bounded resource fixtures; it must not remain an alternative MR dispatch path. Native layout/typed resource backing must attach to the actual JKRArchive and the actual manager-created LayoutHolder/ResourceHolder. In particular, the old ResourceArchiveOwner pre-registers J3D/animation/JMap/BAS resources and replaces BTI/CANM archive cache entries before constructing a holder. That preparation must be moved to a shared SDK/resource boundary before removing OriginalStationedResourceManager's facade. The independent agent is recovering the actual ResourceHolderManager dispatcher while this native ownership seam is audited.

Heap retirement must stop/drain the original file worker before removing request entries or freeing buffers. Layout/model borrowers must retire before FileHolder frees source bytes; original ArchiveHolder then unmounts the wrappers. Original ResourceHolder has an implicit trivial destructor and LayoutHolder's original destructor is empty, so host containers cannot rely on a fabricated Game destructor callback. Required native backing must have an explicit archive/process lifetime and avoid a strong heap-owner cycle inside an archive allocated in that same heap.

Evidence: `source-proof.json`, `wii-compile.json`, the six objdiff reports, and `native-compile.json`. Shared startup link evidence is recorded separately in `../original-game-system-startup-20260912/baseline-link-frontier.json`.

## Actual file-owner retirement and component fixture

`FileLoaderOwnership` drains the original per-file completion queues, including entries whose request-array indices have been cleared. It then cancels/joins the actual original worker and clears its matching singleton before deleting the file and archive entries and request storage. Clearing the singleton before draining would be incorrect: an in-flight original mount callback still calls MR::createAndAddArchive through that singleton. The caller must stop submitting requests before entering retirement and keep all source/target heaps alive until it returns.

`SingletonHolder<T>::release()` is a native process-lifetime addition under TARGET_PC, explicitly authorized by the coordinator under the user's native architecture allowance. It returns the actual pointer and clears its slot. It is not a recovered retail method. The caller must drain borrowers and hold the guest execution gate. This shared template operation replaces the need for per-type symbol-access tricks during restart.

`OriginalFileLoaderTests` uses complete original HeapMemoryWatcher and FileLoader objects with a real disc, without constructing GameSystem or substituting request providers. It links the complete original FileUtil TU privately while global activation is held. It verifies actual OS jam/send queue identities, duplicate suppression, all retail decoded bytes, a caller-owned destination, actual heap-backed archive identity and full catalog contents, original completion states, cleared request metadata, and three worker/archive teardown-and-recreate cycles with exact heap free-space restoration. Its small 64-byte original FileRipper buffer forces streaming refills for compressed inputs. The coordinator rebuilt the shared target with the DVD descriptor correction and the real-disc runtime passed all three cycles, including exact heap free-space restoration. See `shared-dvd-identity-build.json` and the initial `shared-dvd-identity-run.json`; the final catalog-barrier revision also passes in `file-loader-final-run.json`.
