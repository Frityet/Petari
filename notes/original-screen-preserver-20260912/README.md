# Original ScreenPreserver and J2D prerequisites

This bounded activation supplies the actual `ScreenPreserver` translation unit needed by `GameSystemObjHolder`, together with the canonical J2DPicture, J2DPane, JUTPalette, J2DScreen resource lookup and J2DDataManage lookup implementations. ScreenPreserver and the four SDK source files other than J2DPane are byte-identical to the current decompilation reference. Their original-compiler/object comparison evidence already exists in `../original-display-owner-20260912/`; no new reference bodies were authored in this activation.

The native pane retains one architecture correction at `J2DCast_F32_to_S16`: its intermediate float-to-int conversion calls Aurora's existing Gekko conversion primitive. This defines the original saturated integer conversion for infinity, NaN and out-of-range inputs instead of invoking host C++ undefined behavior. The original sign, fixed-point scaling and signed-16 clamp branches remain unchanged. It does not introduce a pane-specific numeric implementation.

`runtime/jut/JutTexture.cpp` keeps its existing mapped texture allocation, original-heap finalizer and construction rollback support. Its previous palette overloads ignored actual TLUT initialization/load and supplied a parallel simplified implementation. These method bodies now use the original SDK source: all three storeTIMG overloads, attachPalette, init, both initTexObj overloads and load. The native JUTPalette destructor retires its real Aurora TLUT object using the existing GXDestroyTlutObj boundary. No separate heap finalizer is registered for an embedded child. Owned embedded palettes are created/reused, external palettes remain borrowed, CI objects receive their actual TLUT identifiers and load dispatches the actual palette before the texture. The destructor now releases an owned embedded palette, and the native resource constructor releases it when later host construction bookkeeping throws. Existing native ResTIMG scalar records and signed 32-bit rebased offsets remain authoritative.

There are no new placeholder picture/pane classes or synthetic successful screen captures. The actual picture uses its original texture array, ownership mask, transforms, TEV setup and GX draws. ScreenPreserver still obtains its image through `MR::getScreenResTIMG()` and the real capture owner. No partial GameSystem is constructed. J2DScreen's existing original resource lookup uses the genuine JKRFileLoader before its actual J2DDataManage linked-list fallback.

`native-proof.json` records seven fresh isolated compilation successes at the current source hashes. `undefined-symbols.txt` captures their link dependencies. The TBox2 assignment is already supplied by actual J2DGrafContext, and the TColor assignment by actual JKRThread; no new forwarding definitions were needed. `source-manifest.json` records the exact thirteen source/header paths and reference identity. `JutTexture.before.cpp` preserves the replaced simplified provider for review.

Production source is ready for the parent startup build; five SDK build entries have been sent to the parent. No shared build, GPU run or publication was performed by this agent. Palette ownership, picture drawing and screen-preservation runtime checks remain pending; compile success does not establish those outcomes. Native raw ResTLUT construction expects an already-native resource record and retained encoded palette bytes. This activation does not claim that raw big-endian archive resources have gained a new typed materialization path.
