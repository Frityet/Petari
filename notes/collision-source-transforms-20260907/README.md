# Collision source transforms

The actual Gateway launch crashed in Mario::recordLastGround during MarioActor::initAfterPlacement: the original ground-recording call requested Triangle::getBaseInvMtx, whose native provider dereferenced a null CollisionParts pointer. Native hit triangles already retain a stable KCL source identity, exact geometry, PA data, sensor and registration lifetime, but that source transform was not exposed through the three matrix accessors.

The shared StageCollisionService now retains stable base/inverse/previous matrix storage per source on first use. It copies the exact registered affine transform and computes the inverse with the original SDK PSMTXInverse; static previous transforms equal the original base transform. Source-vector relocation cannot move these matrices. The cache allocates in the host domain, and requests reject absent, disabled, released, cleared, nonfinite or singular source state. Existing actual CollisionParts-backed triangles retain their original member access. No Game source, ground tuning, actor-specific branch, dummy CollisionParts or fabricated identity matrix was added.

The existing stage-collision-registration target builds and passes all three cases. The new regression obtains an actual hit from a rotated/nonuniformly scaled/translated KCL, records its local point with the same inverse operation as Mario, transforms it back, copies the Triangle, appends64 sources, checks stable pointers, and verifies disable/re-enable/release/clear behavior. results.json and build/run logs record commands/results. Full moving CollisionParts ownership is still a separate unfinished system; these existing registrations are static.
