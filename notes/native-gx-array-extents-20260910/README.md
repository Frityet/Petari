The GX decoder previously learned an unsized array's extent from each primitive's highest index. Each larger index invalidated its upload range, so a large unchanged model repeatedly copied larger prefixes. J3D already knows the exact materialized bytes for every native VTX1 array. Those extents now follow the actual resource owner through Aurora ArrayRegistration; registration occurs after final native allocation, persists through owner moves/source retirement, and is removed before bytes are freed.

The resource integration records each table's actual native offset and aligned byte size, including the real source-backed original CPU-copy footprint where it extends past the physical table. It does not use a broad allocation size or infer table lengths from unrelated neighboring native pointers. Aurora's decoder can resolve original unsized GX/GD array-base commands to these bounded extents, including patched pointers. Explicitly sized bindings retain their own bounds. Unregistered arrays retain unsized behavior.

A coordinated Aurora cache change reuses immutable per-frame snapshots only when current bytes match, including A-to-B-to-A rebindings and invalidations. Modified content still receives a new snapshot; unchanged already-valid bindings preserve their existing source-retirement behavior. Neither change alters Game code or raises a hardcoded buffer capacity.

The resource fixture adds exact extents for S16 positions/normals, NBT, byte colors and texture coordinates, including native-padding exclusion, interior pointers, owner move and retirement.
