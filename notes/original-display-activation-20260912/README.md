This cohort activates the previously recovered MainLoopFramework and actual JUTVideo/JUTXfb factories. It imports the supporting original JUTDirectPrint, JUTAssert, JUTConsole, JUTDbPrint, JUTFont and JGadget link-list translation units. The previous `runtime/jut/JutVideo.cpp` proxy and `WiiVideoService` are removed, including their duplicate video state, synthetic retrace count and callbacks that only recorded events.

`OriginalDisplayLifetime` supplies explicit retained storage for native hosts which exercise scenes without constructing GameSystem. `AuroraWindow` borrows a `DisplayFrameSource` from that owner. `AuroraRenderer` starts the host GPU frame, invokes the original MainLoop beginRender, permits normal Game drawing, then invokes original endRender/endFrame/waitForRetrace before ending the host GPU frame. This runs once per rendered frame, independently of the number of simulation updates. The original fields own the clear color/depth, copy filtering and XFB exchange; there is no parallel native buffer index or fake completion. Standalone renderer clients without a Game display retain their ordinary direct display-copy path.

It drains GX before restoring the previous draw-done callback, destroys the actual MainLoop/Xfb and JUTVideo objects, restores VI callbacks, flushes black/null scanout and waits for that retrace, retires GPU texture identities, releases its DirectPrint object, and finally returns the retained JKR heap. RuntimeContext retires the display before DrawSyncManager. Application no longer shuts Aurora down from `run()` while its service graph still retains these owners; dependency-ordered graph destruction retires them before the window.
