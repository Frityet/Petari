# Compatibility boundary review — 2026-09-19

The compatibility boundary is **not clean yet**. The reviewed Aurora/shared runtime paths do not contain a demonstrated Gateway/rabbit-specific branch that forces the demo forward. However, native replacements still duplicate original game algorithms, one concrete GX workaround changes copy semantics, and older scripted showcase systems remain mixed into the shared source target. Copying an original function into a file named `Compat` is also source-ownership debt: it does not turn that function into platform compatibility.

This review makes no production changes. It compares current source/call paths against the local canonical decomp, SDK and Dolphin references. No new game replay, build, numerical regression, or pixel test was run; the existing archive was inspected read-only for duplicate symbols. These findings must not be presented as proven causes of a particular Gateway visual or gameplay symptom.

## Prioritized findings

1. **P2: GX texture copy rewrites stored alpha.** `aurora/lib/dolphin/gx/GXFrameBuffer.cpp:311-321` clears framebuffer alpha to current destination-alpha state before resolving a copy, even with `clear=false`. Destination alpha belongs to drawn fragments; a copy must preserve stored pixels unless the explicit copy-clear operation applies. This is an inherited generic rendering workaround, not a Galaxy-specific case. Repair/validate the ordinary GX pixel pipeline and remove the copy-time repair; test two alpha regions, no-clear copy, subsequent EFB contents, and true-clear behavior. See [runtime audit](runtime-audit.md).
2. **P2: LiveActor gravity duplicates the original numerical path.** `src/compat/ActorMotionCompat.cpp:10-31` normalizes the already-normalized gravity result again through host `sqrt`, different cutoffs and gates. The original `MR::calcGravity` helper already exists. This active path should preserve the original call/storage semantics, with host lifetime handling kept separate. Immediate calculation in `onCalcGravity` is original and is **not** itself a bug. See [runtime audit](runtime-audit.md).
3. **P2: LiveActor easing replaces original table math with libm.** `src/compat/LiveActorUtilCompat.cpp:341-351` calculates `1-std::cos(...)` instead of the donor's shared `getEaseInValue`/JMath table path, which is already available. This is an unnecessary game-math reimplementation. It has a SphereSelectorHandle caller; this review does not claim that overload was exercised in Gateway. See [runtime audit](runtime-audit.md).
4. **P2: the source audit cannot enforce this boundary.** `scripts/source_closeness_audit.lua:469-476` omits `src/compat` entirely. Its successful run inventories 213 compatibility files but misses 337 source/header files in that directory. It also does not map excluded canonical translation units to actual replacement symbol providers. Add those surfaces and imported-function provenance to the audit; directory names alone cannot establish generality. See [root audit](root-audit.md) and the unchanged tool's [output](source-audit/source-closeness-summary.md).
5. **P2: duplicate lifecycles and legacy showcase policy remain.** `GatewaySpinCheckpoint`, `TitleFileSelectRoute`, and `FileSelectFarVisual` implement content-specific routes/visual policy for old showcase callers, while `src/Game/xmake.lua:99` compiles every scene source into the shared game archive. Keep these separate from production compatibility or retire them. The actual `--original` process uses GameSystem/GameSequence and bypasses these routes, but `src/app/main.cpp:55-63` still makes that process opt-in beside a separate default host lifecycle. Make original ownership the normal game entry and retire unnecessary alternate lifecycle code. See [scene audit](scene-audit.md) for reachability, default-launch ambiguity and exact locations.
6. **P2: a canonical function has two strong providers.** `MR::connectToSceneCrystal` is defined in both `src/Game/Util/ObjUtil.cpp:375` and `src/compat/SceneConnectionCompat.cpp:8`. Read-only inspection of the existing game archive confirms both definitions; see [symbol evidence](duplicate-provider.json). The bodies match the donor, so this is duplicate source/link ownership rather than invented Crystal behavior. Retain the canonical provider and remove the redundant definition. Archive-member selection currently permits the main link, but another consumer can expose the conflict. See [build audit](build-audit.md).
7. **Dormant alternate implementations remain.** `src/runtime/RuntimeServices.cpp:2303-2319` produces a made-up one-frame particle when dynamics are absent. Current original actor/layout effect ownership does not use that entry point according to the scoped caller search. Retire the obsolete alternate service or route its remaining tools through real JPA; do not carry the fallback forward. `StorySequencePlatformCompat.cpp:41-105` also retains an unreachable, incomplete game-flag evaluator; active wrappers use the original checker, so delete the dead evaluator rather than reviving it. See [runtime audit](runtime-audit.md) and [build audit](build-audit.md).

## Original code versus native adaptation

There are three different kinds of code to keep distinct:

- **Original Game/JSystem behavior:** actor states, collision queries, demo/talk/story rules, interpolation, authored factory/resource choices. Import it from decomp, preserving behavior; newly recovered code belongs in decomp first. A copied original body in compat is not a new hack, but consolidating its canonical source owner avoids drift.
- **Host/SDK adaptation:** pointer width, byte order, binary decoding, heaps, lifetime, threading, GX/VI/input/device contracts. Implement these for every caller, preserving observable original semantics. Put reusable Wii-facing facilities in Aurora where appropriate. Class-specific lifetime metadata can be legitimate; it must not choose gameplay outcomes.
- **Diagnostics/showcases:** explicit test probes, external controller scripts, bounded synthetic setup. Keep these outside normal game policy and describe their evidence accurately.

`OriginalMapQueries`' actor-excluding collision filter and the recent original ModelObj/JMap restorations are the right direction. They preserve original generic algorithms and remove local-coordinate/initialization divergence. Authored factory names, Mario's original model-name list, and original scene category constants are not hacks merely because they mention actors. See [build/owner audit](build-audit.md) for displaced original methods and retained provider splits.

The Wii Remote startup screen skip is explicitly permitted by the user. The CP932 literal wrapper is also an explicitly permitted source adaptation. Audio remains outside the requested priority. None should be treated as an unapproved gameplay shortcut in this review.

## Recommended implementation order

First eliminate the active redundant gravity/easing algorithms using original bodies and focused comparisons, and address the GX alpha issue with a pixel-level regression. Then make the boundary audit cover actual linked replacements, consolidate original provider ownership where the old link constraints no longer apply, and remove/isolate stale showcase and effect systems. Do not merely rename files, add actor-name exclusions, or replace missing behavior with successful no-ops.
