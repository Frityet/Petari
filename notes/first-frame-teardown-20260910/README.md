# First rendered frame: native Bright capture teardown

The actual Gateway showcase rendered and saved `first-present.png` with `--screenshot-frame 1 --exit-after-screenshot`, then aborted during cleanup. `command.json` records the exact command and prior binary hash; `first-abort.log` is the complete LLDB run with only abort/assert breakpoints. The debugger explicitly killed its stopped process after collecting all thread stacks.

The first abort is a malloc invalid free of a retained `AuroraBrightVisibilityService::Impl::Capture::drawn_sources` unordered-map node. The call chain is `operator delete` -> `deallocate_jkr_or_host` -> `std::free`, reached by `Impl::reset` during renderer destruction after Game heap retirement. `submit_sphere` allocated this native draw-pass map through the original draw-sync caller's selected Game heap. `begin_capture` moved the map into a pending GPU capture, extending its lifetime beyond that heap. The retired arena no longer participates in the original allocation registry, explaining the final invalid host free.

## Change

`AuroraBrightVisibilityService.cpp` now enters Aurora's existing host-allocation scope at its native public boundaries, including allocation of the implementation and owned backend inside both constructor bodies. Retained source maps, prepared draw maps, capture vectors and their native backend operations therefore belong to host memory. The explicit destructor destroys the implementation within the same boundary. No Game methods, draw ordering, capture readiness semantics, heap lifetimes, or deallocation fallbacks change. The backend interface is a native GPU snapshot seam; its production implementation calls only GXAurora snapshot APIs, so these scopes do not execute original Game callbacks in a different heap.

## Bounded regression

`BrightVisibilityBatchTests.cpp` constructs both service variants and submits two actual draw/capture batches under a real 64 KiB original Game heap. The test requires zero Game heap consumption and verifies that original allocation routing is restored when service calls return. It then retires the child and entire root arena, resolves one ready capture with all exact probes visible, and destroys the second pending capture. Both snapshot handles must be released exactly once. This exercises the actual retained map lifetime from the live abort, without a renderer stub or retaining the original arena. The existing nine behavioral groups remain.

The official `smg-pc-bright-visibility-batch-tests` target subsequently linked and ran with exit 0: all nine pre-existing behavioral groups and the new actual Game heap retirement group passed.
