# Independent lifetime review

The parent and independent compatibility reviewer audited the native callback route against the original SDK source and the changed code. Material findings were closed before publication:

1. Active cancellation originally used Aurora's synchronous retirement shortcut before calling the cancellation request on its caller. The SDK requires immediate return, duplicate rejection, and original -3 followed by cancellation-request 0 in the actual interrupt. The new retained callback slot implements that original route and keeps the real command pointer.
2. Cancel-all/stop originally copied all queued pointers before invoking callbacks. A callback can cancel and reclaim another queued descriptor. The shared drain now removes one at a time; the regression deletes the middle descriptor during the first callback, covering both cancel and descriptor close.
3. Entering the guest scope even for an empty stop queue caused an actual process-exit exception after TLS cleanup. Empty teardown now checks without entering guest state, and an independent subprocess exits with the worker still open after adopting a guest thread.
4. Stopping/replacing the host disc from its worker previously detached that worker and allowed restart before its epilogue finished. The host service rejects this invalid reentrancy before state changes. The original SDK descriptor-close path remains supported.
5. A native retirement identity remains retained while a callback returns, but the callback may already have reclaimed its descriptor. A separate actual delivery phase prevents cancel-all from presenting that identity as an executing command or dereferencing it. The regression deletes its own FileInfo and then calls cancellation-all inside the callback.
6. The empty-safe stop drain initially popped a descriptor before waiting for guest CPU ownership, leaving a WAITING descriptor undiscoverable to another guest cancellation. It now checks nonempty, acquires the guest scope, then rechecks/pops and delivers under that scope. Direct descriptor close/drain was checked for the same race and now acquires its guest scope before queue lookup/removal. The stop regression deliberately cancels and deletes a pending descriptor while the host stop waits for the held guest CPU.

The independent reviewer confirmed the final queue discoverability, completion capture/publication, cancellation result/pointer, self-reclamation phase, and mutex release before CPU reacquisition. No further material finding remained in this bounded review. This does not extend the claim to simultaneous independent native disc-service replacement or complete DVD hardware behavior.
