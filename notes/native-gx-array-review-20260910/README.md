# Bounded independent native GX array review

Reviewed the new Aurora ArrayRegistration/lookup, decoder integration, per-frame exact-byte snapshot cache, and root J3dGeometryData registration lifetime. No source edits or builds were performed. No concrete blocking defect was identified in the reviewed version. Exact reviewed files are hashed in source-manifest.json; runtime/build evidence belongs to the implementation agents and root.

- Extents: ArrayRegistration rejects null, zero, >u32 and uintptr-wrap ranges before arithmetic. Ordered-map predecessor/successor checks reject conflicting overlaps, allow touching ranges, and permit only exact same-base/size/endianness duplicate owners. find_registered_array returns the remaining bytes from interior pointers; pointers before a range or at its exclusive end have no extent unless they actually begin another registered range. No allocation-size inference is used.
- Metadata lifetime: registrations contain a private shared state and base key. Registration/lookup/reset hold the same mutex; returned metadata is copied, not a map reference. Move and duplicate-owner destruction preserve the registry entry until its last token. The registration itself owns metadata only; its documented caller contract still requires live unchanged borrowed bytes until FIFO consumption. Metadata locking does not authorize concurrent mutation/free of source bytes.
- Root resource lifetime: vertex arrays are registered only after builder.finish creates final native storage. Published sizes match materialized scalar-aligned source spans, excluding inter-array native alignment padding. Empty spans are skipped by the final guard. Storage declares vertex before vertex_arrays, so reverse destruction removes registrations before freeing the native block, including constructor unwind. J3dGeometryData move transfers the unique Storage owner; no array address changes. Source archive retirement is independent because native values were copied into the retained block.
- Byte order: 16/32-bit scalar arrays are already materialized numerically for the host. Packed native color conversion is also retained. Registration publishes host byte order for these exact native tables. Unsized decoder commands resolve the final pointer at replay, so a later GDPatchArrayPtr is honored. Explicit-sized commands do not consult the registry, preserving their authored cap and byte order. Removing registration and replaying the unsized binding returns it to the old unknown-extent path. All accesses still pass require_array_span and its overflow/cap checks.
- Snapshot semantics: cache reuse compares the complete requested current-byte prefix against an owned snapshot and requires an existing uploaded range. Wider or changed data gets a new storage upload; a smaller identical prefix can safely reference the prior immutable upload. Raw-byte reuse does not require byte order in the cache key because shader decoding retains array.le separately. Existing valid array bindings continue to use their already-owned upload; invalidation/rebinding causes the new content comparison. The cache does not claim to detect unsynchronized CPU writes while the same valid GX binding remains cached.
- Thread/frame boundary: normal aurora::end_frame drains FIFO before fifo::end_frame clears snapshots (aurora.cpp:286–287). fifo::drain waits on the worker's released processed watermark with acquire semantics. Shutdown joins the worker before clearing the snapshot map. Metadata operations are separately mutex-serialized. No concurrent unordered-map clear/update was found on the normal production path. gfx::begin_frame resets every attribute cachedRange (gfx/recording.cpp:587), so discarded frame upload ranges are not reused next frame.

Read the new ownership/decoder tests: exact/interior bounds, duplicate owners, moves, conflicting overlaps, endian preservation, patched GD pointer replay, explicit caps, growing registered indices, and unknown-source fallback. Root geometry tests assert exact S16/NBT/color/texcoord extents and source/move/retirement. These were inspected, not independently run by this review.
