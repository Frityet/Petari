# Next non-audio compatibility removals

Read-only inspection after round17 source integration. No production edits, build or tests. Remaining non-audio scope is 11 code/header files (2,180 lines) plus two generated CP932 data files. Round18's planned SceneDrawBufferService removal should precede the full actor-registry deletion.

## Small independent batches, ranked

1. **Delete dead ActorRuntimeRegistry APIs immediately.** No call sites in src or tests for `retain_name_obj_host_name`, `destroy_name_obj_runtime_objects_since`, `actor_model_resource_data_if_present`, `register_actor_binder`, or `release_actor_binder_state`. Remove the now-unwritten `NameObjRuntimeState::host_name` field with its setter. `actor_binder_config`, `has_actor_binder`, `actor_lod_ctrl_runtime_state_count`, and `name_obj_runtime_owner` have only fixture consumers; remove those synthetic contracts or use actual Binder/actor ownership fields. Do not retain counters solely for fixtures. This shrinks the eventual owner migration without moving any service.

2. **Remove MetrowerksAlignedNew.cpp + JkrAllocationRouting.hpp (2 files).** JKRHeap.hpp already declares the original integer-alignment and heap-placement overloads; integrate their definitions and the ordinary/aligned C++ new/delete overrides into the actual JKernel allocation owner. The routing implementation currently at the end of JkrAllocationDomain.cpp belongs beside `JKRHeap::releaseAllocation` and the heap's current-selection mutex. Keep Aurora's existing allocation routing policy (`aurora/allocation.hpp`) as the shared host/client selection boundary. Preserve new-handler retry, nothrow forms, array/sized/aligned deletes, negative alignment meaning tail allocation, native pointer alignment, and provenance checks. First move root/MEM2 arena range publication to actual heap/arena owners, then remove the routing header and provider. Do not make Aurora depend on Game heaps. This can be done before eliminating all domain handles.

3. **Dismantle MetrowerksStdCompat.hpp (1 file), not rename it.** Its contents already have distinct owners:
   - Delete duplicate NO_INLINE and ALIGN_NEXT/ALIGN_PREV definitions: Aurora revolution/types.h already supplies them.
   - Put `__fabs`, `__fabsf`, `__abs` and original RVL degree/array macros at the compiler/math/RVL SDK headers; retain single-precision pi operation order and unsigned INT_MIN handling.
   - Put the mixed-long integer clamp overload directly in Game/Util/MathUtil.hpp next to the existing s32 implementation; its getRandom(long,long) declaration is already there.
   - Placement new declarations come from canonical JKRHeap.hpp.
   - Remove forced inclusion of LiveActor.hpp and DirectDraw.hpp by adding explicit includes to the actual callers missing types. These are Game include defects, not SDK behavior.
   - Only two bare `DUMMY()` definitions remain, in Gravity/ParallelGravity.cpp and Map/RailPart.cpp. Make those scratch emitters locally static and delete the global function-rewriting macro.
   - Include Aurora's already restored functional.hpp where needed. Keep the stdio alias boundary separately until batch 4; it must appear before system stdio declarations. Update the Game/tests forced-include flags rather than invent a new all-purpose prefix header.

4. **Consolidate MSL formatted output into its general SDK owner (3 files).** Remove MetrowerksPrintf.hpp and MslPrintfCompat.cpp/.hpp after integrating the narrow-string formatter and original stdio declaration boundary into Aurora's MSL C runtime surface (canonical printf implementation/header corresponding to decomp/libs/MSL_C/source/printf.c and include/stdio_api.h). This is a real standard-library API implementation, independent of Game. Preserve the currently implemented MSL Pascal strings, byte precision, low-byte wide-string conversion and padding; do not substitute host snprintf. Preserve explicit native vararg widths for host pointers/long, bounded output, and native positional/locale extensions. Crucial: build the provider without its own symbol aliases, otherwise host numeric formatting recurses. Current wiring is src/common/xmake.lua plus a Game exclusion; migrate that exact boundary. No broad Game source edits required.

5. **Remove the CP932 trio through the existing encoding owner (3 files).** Cp932Literal.hpp is a general constexpr UTF-8 encoder, not a gameplay workaround. Integrate its compile-time encoding API with the existing resource/TextEncoding.hpp owner, and store the frozen mapping beside the encoding implementation. Delete the compat namespace/path and update literal includes mechanically. Retain the array-lvalue return, static storage, embedded NULs, strict invalid-input diagnostics, and Windows CP932 choices. Do not replace literals with runtime temporary strings or assume Shift-JIS is identical. The frozen table contract is documented by tests/test_cp932_literals.py: 9,280 non-ASCII mappings and SHA-256 46778ae55afa614d3ece7e4f7160d9f1205626f09a461e6d7a933b57b582d600. No source rewriting is needed during a build. If encoding is promoted to Aurora later, move the shared encoding facility coherently, not a Game-specific CP932 shim.

## Larger closures after scene draw ownership

**ActorRuntimeRegistry.cpp/.hpp (717 lines): split by actual owners.** LiveActor directly owns Spine, RailRider, StageSwitchCtrl, ActorLightCtrl, LodCtrl, Binder, animation helpers and sound resources. ModelManager's existing shared native owner must stay retained by both LiveActor and the real DrawBufferExecuter prototype; MarioAnimator is another explicit borrower. Its raw Game fields remain observations of those actual members. Replace the registry's resource map with these members and idempotent LiveActor native retirement, preserving the present prepass before child/scene heaps retire.

NameObj has separate work: generation/claimed ownership belongs on actual NameObj; construction order and rollback belong in NameObjHolder/SceneObjHolder transactions, including objects constructed before registration. Existing markers are still live in GameSceneBinding, SceneObjHolder and OriginalGameApplication, so they are not dead APIs. Replace the global map's dynamic_cast sweep with actual holder/borrower retirement: NameObjGroup/LiveActorGroupArray, TalkDirector, DemoDirector/Executor and BaseMatrixFollowTargetHolder. Keep retired-address generation checking for NameObjCategoryList callbacks, clipping, LightPointCtrl and shadow borrowers. HitSensorKeeper retirement must still invalidate other keepers' taking/taken/contact pointers and pending MsgSharedGroup senders through actual holders; ClippingActorHolder/GroupHolder must still clear LiveActor backreferences. Do not delete these safety behaviors with the map. The upcoming draw batch removes one coupling; this is not a simple namespace/path change.

**JkrAllocationDomain.cpp/.hpp (474 lines): remaining owner split, not the next small batch.** JkrHeapRuntime's physical arena belongs to the actual root heap and process memory owner; MEM2 allocation/binding and ARReset ordering belong to the Aurora arena boundary plus Game HeapMemoryWatcher lifecycle. Associate retained lifetime/weak borrow state with actual JKRHeap objects instead of the global DomainRecord linked list. The current domain abstraction also creates real solid child heaps and retains parents, so deleting it without native heap tokens would break resource owners. Replace JkrAllocationScope with canonical JKRHeap::CurrentHeapScope plus Aurora client allocation routing and a retained actual heap token; preserve previous-heap lifetime, shared mutex ordering, and do not hold that mutex across original async waits. `JkrHostAllocationScope` is only an alias: consumers can use Aurora's existing HostAllocationScope directly. Budget values stay with GameResourceRuntime/actual process callers. Production child-domain creation still exists in ScenarioCatalogOwnership, ParticleResourceOwnership, OriginalDisplayLifetime and disabled-object audio; those callers require actual owner migration, not removal as test-only APIs.

Recommended immediate implementation after round18: dead API pruning + canonical JKernel new/delete integration, then dismantle the forced prefix header. These are bounded, independent of the larger actor/heap lifetime migration and remove three complete compat files without sacrificing the existing lifetime contracts.
