# Next actual GameScene lifetime boundary

The current extraction preserves StageHostScene destruction: the initialization service retires roots and bindings before the Scene base deletes its SceneObjHolder. A real GameScene must run its own destructor body while NPC/message/pointer and scene-object services are still published. Its base Scene destructor then deletes the holder. Simply declaring unique_ptr<GameScene> and unique_ptr<StageInitializationService> in either member order cannot insert stage retirement between those two original destructor bodies.

The next implementation should provide an explicit native Scene lifetime binding. The original Scene base destruction boundary must invoke registered native retirement before deleting its own real SceneObjHolder/list executor, after the original GameScene destructor has already executed. Keep this host lifetime hook outside Game by retiring the existing divergent Scene.cpp backend into compatibility and restoring the reference copy; alternatively a narrowly justified native destructor hook is an architecture/lifetime adaptation. Do not call a GameScene destructor twice, manually invoke only its body, use an unrelated Scene cast, fabricate a GameSystem, or leave the holder pointing into freed storage. A binding must also unregister on constructor/init failure and remain safe if native service destruction happens first.

The actual scene Game allocation domain should be created before original GameScene construction and retained until all its native services and original children are retired. SceneObjHolderBinding currently creates a separate 8MiB domain internally. Extend its explicit construction contract to accept an existing retained scene domain and use that exact domain for the Scene, executor and original object graph. Metadata/control-block allocation must remain in the host domain. A second hidden scene heap would make teardown and allocator claims misleading.

GameScene::initSequences allocates raw non-NameObj owners (opening-camera NerveExecutor, pause-control NerveExecutor and PauseButtonChecker), plus original LayoutActor children and a cloned callback. Native ownership must capture the NameObj descendants once and retain each non-NameObj dynamic type explicitly. Original GameScene's destructor does not delete these raw children. Keep the pause callback alive until its layout owner is retired, release all Spine objects while their original domain exists, and avoid constructing absent objects just to pass an event request.

Executor integration is being prepared separately under original-scene-category-execution-20260907/queue-owner. Scene must own one genuine SceneNameObjListExecutor, and SceneDrawBufferService should borrow the exact DrawBufferHolder that executor owns while retaining actual model prototypes. The existing aggregate scheduler is not an original NameObjExecuteHolder and must not be cast to one. Category callback guards and original fixed-list membership order need one coherent ownership migration.

These are implementation requirements and an ordering analysis, not activated source or runtime proof. The current three missing MR scene-event functions remain unresolved until a real active GameScene and these dependencies exist.
