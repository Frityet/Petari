## Mandatory game behavior

GamePauseSequence::startPause enters the actual pause menu; GameScenePauseControl exits it; GameSceneScenarioOpeningCameraState stores30 in the actual _830 counter. EnterPauseMenu moves sequence/stream manager volume tozero over18frames, stops affected SE categories, pushes the pause category preset and enters a19-frame transition. updatePauseMenu finishes that transition, then pauses BGM and rhythm ME. Exit sets a21-frame transition, restores20-frame BGM/stream gains and previous SE preset, and unpauses. AudSystem::frameWork advances these timers and the _830 suppression timer. The original startSound/startLevelSound consult reset/menu/timer/trigger/level state before starting sound. A flag-only proxy or writes into JAudioPlaybackService storage would omit these decisions.

## First coherent migration

1. Restore the original JAISound/JAISoundHandle and actual typed manager/stream declarations at the shared SDK boundary. A handle must hold one real JAISound pointer and that sound must reciprocally hold its current handle. Use original attach/release/stop/status/fader/parameter bodies. Preserve complete original fields, adapt JAISoundID byte layout and named/raw flag bitfields using existing Aurora endian/PPC helpers, and keep backend VoiceToken associations outside the original object layout. A backend token alone is not a JAISound object.
2. Retain actual JAIStream/JAISe objects in their real managers' JSU lists. Route the JAS playback boundary to the current working PCM decoder/mixer; lifecycle callbacks return on the owning game/audio update thread. Prepared/started/stopped state must follow real voice events. Unsupported sequence decoding continues to reject a start without attaching a handle or adding a live list entry. Do not invent a playing sequence to let Game queries advance. The stream path is the smallest complete backend tranche because the existing decoder already supports the retail stream assets; retain its actual original JAIStream/manager owners and put platform streaming at JASAramStream.
3. Instantiate the complete AudSystem constructor/resource child graph in a process-owned Game allocation domain. AudWrap::getSystem returns its real msBasic. Once this exists, expose the embedded mBgmMgr and actual mVolumeController/mSeMgr category parameters and move all permit/menu/timer queries to the real AudSystem fields. Retire the separate native BGM manager, category backing and permission flags in that same cohort. Reuse the existing valid PCM output and decoded asset paths rather than creating a second playback service.
4. Bind original frameWork once per game audio frame and preserve the actual sequence/stream manager gain ramps, per-category stops and BGM pause lifetimes. Validate pause entry/exit19/21-frame boundaries and _83030-frame gating with real handles/manager membership and PCM voice pause/gain, then construct the mandatory GameScene children. Full save and stage-flow owners remain separate dependencies.

## Native ABI migration inventory

handle-token-abi-users.json identifies the five current files calling token extensions: the Aurora handle header, JAudioPlaybackService.cpp, AudioFacadeCompat.cpp and existing tests. Every translation unit including the header must rebuild coherently. The current BGM service has its own handle plus AudSingleBgm::mHandle pointing to the same token; original JAISound permits only one attached handle, so the canonical Game mHandle must become the sole attachment and callers must receive it directly. Do not retain a second token attachment compatibility path.

JAudioPlaybackService currently coalesces level voices by sound ID and carries its own refreshed/lifetime state. Original JAISoundStarter refreshes per-handle lifetime; separate actors can play the same ID concurrently. The migrated voice registry must key actual sound identity, keep only decoded recipes cached by ID, and let original lifetime fields control refresh/retirement. Current per-service trigger/level booleans must disappear when actual AudSystem owns _82B/_82C. Its category owner currently retains16 independent parameter records and a controller with null mSystem; those must be replaced by real mSeMgr.mCategoryMgrs records and the constructor-created controller. AudioFacadeCompat's static s_bgm_manager must give way to the actual embedded manager. DisabledObjectAudioService must be audited when actual AudSoundObject/JAUSoundObject owners are constructed; its current explicit absent-object behavior cannot back a successfully exposed original system object.

## Validation requirements for the first draft

Use original JAISound bodies in an isolated executable before production migration: reciprocal handle attachment, reattachment stopping the prior sound, handle destruction detaching without stopping, immediate stop detaching, fade-stop timing under pause, prepared lock/unlock, level refresh, and manager removal only after real voice completion. For stream integration additionally assert real JAIStream list identity, exact PCM start/stop callback order, prepared gating, two concurrent streams and same-ID independent effects, retirement across repeated process owners, and existing retail decoder/mixer regression hashes. This report does not claim those runtime checks have yet passed.
