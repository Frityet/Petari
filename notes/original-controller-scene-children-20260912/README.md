## Actual owner and selection path

`SceneInitializationBinding` now borrows the actual `SingletonHolder<GameSystem>()->mSceneController`, and fails when it is absent. The ordinary host `GameSystemService`/`GameSystemSceneControllerService` still requests `StageHostRequest` through RuntimeContext and SceneLifecycleService; that graph does not construct the original GameSystem singleton. An independently constructed controller assigned into an otherwise empty GameSystem would not close this owner boundary.

Original `GameSystem::init` creates JKRAram, GameSystemObjHolder (actual FileLoader/NAND/NameObj registration and embedded ErrorMessageArchive), actual GameSystemFontHolder/embedded font, GameSequenceDirector, GX/FIFO/DrawSyncManager, then GameSystemSceneController. The controller constructor allocates its NameObjHolder and Spine plus the original Intermission, PlayTimer and ScenarioSelect scenes. It is followed by the full GameSystemObjHolder::init, error/reset/home-button/stationed owners. `tests/OriginalGameSystemStartupTests.cpp` is the existing complete-init diagnostic: it calls actual GameSystem::init and intentionally does not construct RuntimeContext's competing children first. The previous startup linker frontier is a historical snapshot; the fresh coordinator build remains authoritative.

Stage selection is the original chain `MR::requestChangeStageInGameMoving` → `GameSequenceFunction::requestGalaxyMove` → actual `GameSequenceProgress::requestGalaxyMove`. After actual save/story/comet updates, it fills `mNextSceneControlInfo` with scene, stage, scenario, selected scenario and start JMapIdInfo, and calls `requestChangeScene`. The controller's actual initializeScene publishes those into `mCurrSceneControlInfo` with `updateSceneControlInfo`, selects the original scene heap and initializes the real scene. The `MR::getCurrentStageName`/scenario queries read these original fields. Setting only a scenario number leaves both stage names unset and is not an equivalent boot path.

Fonts likewise require the actual process owner. `GameSystemFontHolder::createFontFromEmbeddedData` receives the real mounted ErrorMessageArchive, decompresses its localized EmbeddedFont.arc, mounts it and initializes original ResFont. Later, actual stationed archive completion calls GameSystem::initAfterStationedResourceLoaded: this receives Font.arc and replaces the early embedded font with Message/Picture/Menu/Number/Cinema fonts. It also initializes original ScenarioDataParser, PlayTimer/ScenarioSelect layouts, sequence children and effects. Layout compatibility queries now borrow that real font holder; independently loading a font archive would not initialize the rest of this process graph.
