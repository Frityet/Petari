# Actual original scene execution owners

The scene now lends its complete original `SceneNameObjListExecutor` to the native scheduler. This executor owns the only `DrawBufferHolder`, together with the original movement, animation and draw category lists. `SceneExecutionBinding` owns the scene-wide `SceneNameObjRegistry` and creates the original execution requirement holder (4096 slots), StopSceneController and SceneNameObjMovementController before client construction. The SceneObj holder owns those actual NameObjs.

The complete `NameObjExecuteHolder`/`NameObjExecuteInfo` implementation is imported outside Game, with its six GameSystem lookup expressions replaced by the typed current executor binding. Its request states, initial connection handling, per-axis connect/disconnect operations and queue scans are retained. Native boundaries add capacity rejection, lifetime registration and harmless handling of already retired objects. Both original ObjUtil `connectToScene` overloads are restored: the LiveActor overload registers, while the NameObj overload also requests both connections. The previous native SceneFunction implementation moves outside Game and that Game file is restored to its reference contents.

Category snapshots now follow the original arrays, including original swap-with-last removal order. Each callback verifies registration identity and current membership. Metadata contains diagnostic connection snapshots, but cannot activate/deactivate draw executors independently. New NameObjs after initial placement grow the same typed original category storage before their original queue slot becomes eligible for connection; an active model draw registration still requires the original pre-allocation registration phase. This remaining late model limitation is explicit rather than replacing original draw ownership.

Permanent retirement requests and applies only that object's own disconnect operations, tombstones its original slot and resets its `mExecutorIdx`. It does not flush unrelated pending requirements. Scope rollback uses the same path. The binding remains available while SceneObj owners are destroyed; the NameObj destructor notifies the scheduler when the borrowed requirement holder itself retires. Finally the draw service fences actual model work, deletes the same original draw holder, nulls the executor field and releases retained model owners. The original executor can then be destroyed once. CPU-only executors require no GPU FIFO fence.

The parent owns the exact LiveActor lifecycle restoration, native clipping membership, NameObj lifetime/registry and movement controller cohort. The aggregate scheduler invokes the original movement controller once and applies requirement phases after clipping and at frame end. The complete original SceneExecutor import remains the parent's next phase; no GameScene state imitation is introduced here. Camera-before-clipping and the one sensor pass remain explicit category boundaries.
