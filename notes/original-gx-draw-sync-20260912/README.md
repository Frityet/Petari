# Shared GX completion and original layout texture access

The original talk pipeline needs real GX draw-sync callbacks. The previous Aurora DrawDone implementation reported FIFO decoder completion before the render worker had even submitted its commands. Original TalkPeekZ and StarPointerPeekZ cannot safely use that as EFB completion. Work in progress adds partial frame submission with upload storage handoff and real GPU completion, preserving the active render targets and command-stream order. The existing StarPointer-specific snapshot adapter has not yet been removed: full DrawSyncManager ownership and breakpoints remain integration requirements.

A separately validated prerequisite for original NW4R TexMap is complete GXGetTexObjAll and GXGetTexObjLODAll. They read the existing native texture object, preserving native pointer width and the SDK's fixed-point register semantics. Original SDK spelling aliases _GXTexObj and _GXTlutObj now identify those same native objects.

The aggregate getter regression exposed an existing shared sampler decoder error: GX_LIN_MIP_NEAR and GX_NEAR_MIP_LIN were reversed. The decoder now follows the original HW2GXFiltConv table in decomp/src/RVL_SDK/gx/GXTexture.c. Both LOD bias setters now convert negative fixed-point values through a signed integer before narrowing to u8; direct negative float-to-u8 conversion is undefined in native C++.

Validation: the standalone smg-pc-aurora-texture-object-tests target builds and passes texture identity plus 60 sampler combinations (all six minification filters, both magnification filters, and five signed/clamped bias cases). It also checks LOD clamping/quantization and individual sampler setter consistency. The target depends on Aurora only; this is not evidence that the original talk cohort or GameScene links or runs yet.

## GPU completion checkpoint

GXSetDrawSync now emits the original BP interrupt-token and token registers; FIFO decoding treats them as ordered completion boundaries. GXReadDrawSync observes the completed token. GXDrawDone and draw-sync callbacks now wait for submitted GPU work rather than just decoded commands. Both callback setters serialize retirement against an in-flight callback and support self-unregistration.

Partial frame submission rotates mapped upload storage, retaining earlier CPU bytes and GPU offsets, unmaps and submits the encoded prefix, waits for actual WebGPU queue completion, and continues loading the same attachments. A synchronous callback's first GXPeekZ captures the physical EFB and subsequent peeks reuse that readback until callback return. This also works after frame recording ends and while an offscreen pass is active. Readback futures are retired before recycling their slots. No Game actor or stage identity is used in this mechanism.

The renderer now waits for a missing compiled pipeline instead of dropping its draw. This preserves cold-start rendering at the cost of first-use compilation latency. The former optimization that held earlier EFB commands while recording offscreen work is removed: their original submission order is now preserved. Generic pass continuations retain depth/stencil/color policies and load earlier attachment contents, including when the caller requests final discard.

Validation on Metal: all five final standalone targets pass (final-validation.json records binaries, hashes and exit codes). The main proof exercises 13 callbacks, exact depth at two draw positions, more tokens than readback slots within one frame, display-list recording/replay, zero/high token values, self-unregister and continued token register writes, callbacks outside frame recording, and a second frame reusing upload storage. A fresh empty shader-cache directory is supplied. The independent pass proof checks an EFB token while offscreen is active and GPU pixels from a split color/depth/stencil pass whose final stores are Discard. Existing depth-texture and clipping regressions pass too, along with the 60-combination texture-object suite.

The initial deadlock captured in draw-sync-hang.sample.txt was a self-drain through the public is_frame_active query from the FIFO worker; the implementation now uses the recording boundary directly and no longer calls that draining query in callback dispatch. Independent review identified the deferred-EFB and generic attachment-store defects described above; both are fixed and covered by the extra real-GPU test.

Remaining integration: original DrawSyncManager needs general FIFO breakpoint/address lifetime support, actual process/scene callback ownership and guest execution scheduling. StarPointerDepthOwnership remains active until that replacement is complete. Ordinary GXPeekZ outside a callback still uses its existing asynchronous path; this checkpoint only makes the draw-sync callback contract synchronous and accurate. Mid-frame storage transfer currently copies the accumulated upload prefix, a correctness-first implementation whose cost has not yet been measured in a full gameplay run. These focused GPU passes do not prove original dialogue or bunny/Rosalina progression.
