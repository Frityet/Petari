# Render/effects compat deletion audit — 2026-09-25

Scope: **all 80 files / 14,715 lines** in `render-effects-scope.json`. Every file was read by a full-text source scan and compared with relevant current donor sources; nonexact J3D body diffs and the Game-specific/native ownership implementations were reviewed. All 80 hashes matched the supplied snapshot at audit completion, before the separately requested Packet migration. Reference: decomp `1a126cb5d`.

`render-effects-audit.json` has one entry per file with concrete destination, disposition, dependencies, evidence symbols/donor locations/source references, and confidence. Counts: 64 restore-original-owner, 10 narrow-game-adaptation, 4 needs-investigation, 2 delete-unused. **Nothing is retained in `src/compat`.** General host functionality has a real JSystem/resource/renderer/Aurora owner; it is not relocated as a renamed compatibility directory.

The source scanner is a lexical aid: comment/whitespace-normalized whole function matches demonstrate copied implementation, not semantic correctness. It can miss overload/operator/inline definitions; the manually assigned owners take priority. Raw per-file scans and all nonexact J3D comparisons are retained in `render-effects-source-scan.json` and `render-effects-j3d-diffs.txt`. The source-reference list records concrete calls/includes where present; its fallback build-provider entry is not claimed as proof of dynamic use. No runtime/build validation was performed for this audit.

## Ranked removal work

1. **Restore the original light-data system as one unit.** `LightDirectorCompat.cpp:42` calls a null archive loader, omits `mZoneDataHolder->initZoneData()`, and then fills the host cache. `LightFunctionCompat.cpp:152-160` returns null/zero for all archive/parser methods and `:243` has an empty area-data decoder. The original `LightDataHolder.cpp`/`LightZoneDataHolder.cpp` fully implement the missing table ownership. The active alternate cache is fed by `StageLightSceneBinding` in `OriginalSceneSupport`; `render/light/LightData.cpp` returns the stage default for a missing mapping, whereas original LightZoneInfo returns the global default name. Restore `Game/Map/{LightDirector,LightFunction,LightDataHolder,LightZoneDataHolder}.cpp` and `Game/Util/LightUtil.cpp`, then delete that alternate data path. Merely moving LightFunctionCompat would preserve the wrong behavior.

   There is also concrete coordinate drift: compat `blendActorLightInfo` directly lerps position and copies `mIsFollowCamera`; original `blendActorLightPos` converts between camera/world spaces before blending. Compat `calcLightWorldPos` rebuilds a camera basis from the last pose with a fallback; original uses the actual camera matrix inverse. `loadAllLightWhite` uses different coordinates in its runtime state path. Restore original calculations and let GX uploads reach Aurora.

2. **Canonical Packet restoration is the bounded first implementation batch.** `J3DPacketCompat.cpp` consists of 32 original methods (30 exact normalized matches), but its `newDifferedDisplayList` turns allocation failure into success. Its static register table contains eight entries while iterating seven, so it includes ambient color and omits the indirect-stage entry relative to current donor's seven-entry table. Restore the entire canonical `JSystem/J3DGraphBase/J3DPacket.cpp`, align `J3DPacket.hpp` return type, delete the compat provider, and add the canonical build file once. Preserve SDK allocation/GD/interrupt calls and the existing native serialized entry scope. A source-only equality/error-flow check is appropriate; true heap-exhaustion testing would need to exercise the real JKR behavior rather than a fabricated allocator path.

3. **Restore canonical material block behavior, then reunify the remaining J3D fragments by owner.** `J3DMatBlockCompat.cpp` has 135 exact normalized donor methods out of 146 detected. `J3DColorBlockLightOn::diff` differs materially: it skips `diffLight` and ignores the light-count mask. Restore donor dispatch, retaining big-endian packed-color reads. `J3DTevsCompat.cpp::loadTexNo` also removed signed s8 LOD casts present in current donor. Avoid a bulk copy without header/provider reconciliation: `J3DMaterialHelpersCompat`, `J3DSysCompat`, `J3DModelDataCompat`, and `J3DTransformMtxCompat` each mix methods from multiple real owners. The JSON includes per-symbol donor locations.

   Especially low-risk copied sets are Cluster (7/7 exact), MaterialAnm (7/7), MaterialAttach (9/9), Material factory helpers (10/10), Material helpers (19/19), Material variants (17/17), ShapeTable (2/2), and SkinDeform (2/2). The original empty vertex-color calculation is intentional donor code; it is not evidence of a PC stub.

4. **Delete the parallel shadow definition/factory path.** `ActorShadowCsvCompat` reimplements the CSV defaults, type dispatch, position binding and controller setup that already exist in `Game/Util/ActorShadowLocalUtil.cpp` and `ActorShadowUtil.cpp`. `ShadowControllerOwnership::add` replays these definitions into original objects with a second drawer switch; only circle and the selected volume kinds actually construct drawers there. Original CSV supports ten kinds. Restore original creation/query functions, eliminate ActorRuntimeRegistry's replay metadata, and implement needed destruction/unlink/stable borrowed-name ownership in `ShadowController`/`LiveActor`. Original query fragments are mostly exact donor functions and can merge directly with provider checks.

5. **Restore the blur algorithm and solve its EFB requirement explicitly.** `CapturedFrameBlurService` creates a new history owner, uses an offscreen target, skips history on the first frame, hardcodes 608 coordinates and leaves camera projection/view restoration out. Original `FullScreenBlur.cpp` draws to an EFB scratch region using scissor offset 1584, captures at y464, samples the original blur texture and restores camera matrices. This deserves investigation of generic Aurora EFB copy/scissor behavior before deleting the replacement. If a narrow host fallback remains necessary, place it in the actual FullScreenBlur owner. Existing CenterScreenBlur tests assert the service architecture and must be updated; they are not proof of exact original rendering.

6. **Move teardown into actual effect/image owners.** `EffectSystemOwnership` and `ImageEffectOwnership` preserve important real resource and borrowed-callback lifetime behavior but express it as external maps/ID switches. Implement native destruction/initialization in EffectSystem, EffectKeeper, PaneEffectKeeper, MultiEmitter, ImageEffectDirector, Bloom/DoF/Water owners. Retain callback retirement before deleting keepers (including replaced one-shot emitters), texture cleanup, actual scene heap and catalog. Delete the separate ownership maps/fixture-only resource branch once callers migrate. Do not simply drop lifetime code and create use-after-free bugs.

7. **JPA game overrides belong in original Game/System/Overwrite.cpp.** `OriginalJPADraw`, `OriginalJPAFields`, `OriginalJPAEmitterInit`, and `J3DShapeMtxGameCompat` provide original SMG overrides, not generic library replacements. Current decomp Overwrite contains their methods, including JPA field normalization, draw stripes/billboards and ShapePacketUserData texture matrices. Restore them there with original FP compilation settings and only required native user-work pointer/lifetime additions. Generic JParticle files must not define the same overrides twice.

8. **Retain general native mechanics at their real owners.** JUTTexture should own mapped image leases and destruction instead of a process map plus construction interception; resource/Mem1ResourceHeap remains the mapped allocator and Aurora remains the GX copy/device owner. J3DSys should own the serialized command/traversal context used by native entry; original mutex order, GD pointer, interrupt restoration and exception rollback must survive. DrawSyncManager/GameSystem should own their actual worker/heap/callback lifetime. Renderer J3dMaterialRuntime may retain storage adaptation for decoded data but should call the original hierarchy builder instead of `OriginalJ3dJointTree::link_joints` duplicating it.

9. **Delete the unused J3dSystem forwarders immediately after include cleanup.** `load_j3d_view_matrix` and `j3d_view_matrix` appear only as declarations/definitions in the source; DrawUtil still includes their header but does not call either. Actual paths already operate on `j3dSys.mViewMtx`.

## Required boundaries during deletion

- Keep big-endian file/display-list reads, native uintptr_t relocation, native sizeof allocation accounting, stable mapped resources, explicit PPC conversion/shift behavior, and paired-single scalar/FMA behavior.
- Keep game-specific ownership cleanup in owning Game classes, and original algorithms at their original source owners.
- Keep Wii GX/OS/device semantics in Aurora; retain resource validation/decoding in the existing resource subsystem.
- Remove each compat provider and adjust the wildcard/canonical build registration atomically. Do not enable full canonical files alongside fragments that still define the same methods.
- Validate rendering, callback retirement and heap lifetimes after consolidation. This audit does not establish wakeup-through-Rosalina visual completion.
