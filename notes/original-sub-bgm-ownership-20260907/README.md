# Original Stage/Sub BGM ownership

The one stage-only native playback path is replaced by a shared BgmLane API owning two real stream slots. All service consumers are migrated; there is no alternate legacy playback implementation. Each lane has its own token, canonical backend handle, preparation lock, pause and stop state. Native RuntimeContext and MR sub starts now return actual playback results and record resolved events only after a real voice starts. The former logical-only successful sub-start path is removed.

The native AudBgm header now reflects the existing original typed class layout: common volume/rhythm owner, separate Single/Multi handle members, typed JAISoundID, original bool moveVolume return types. SDK-backed inline queries are native declarations; their providers synchronize the real per-object handle with its backend token. The complete original Game source is retained unchanged and excluded from native compilation, with JAudio backend boundaries outside Game. Original AudBgmVolumeController's five faders, stage interruption from active sub music, auxiliary/NoteFairy gain product, and actual next-BGM request slots now drive concrete native behavior. Keeper exhaustion remains nullable. Both scene and RuntimeContext teardown explicitly detach facade handles before retiring native audio.

Full section-one JAS music-sequence decoding and Multi-BGM rhythm/stream synchronization remain disabled. Such starts create no replacement voice and no successful playback event. Malformed resource/ID failures still report errors. This is an explicit audio capability limit, not a claim that BGM_PINCH or the rhythm graph works. Stream playback on both lanes is real.
