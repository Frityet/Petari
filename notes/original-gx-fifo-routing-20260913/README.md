# Native GX FIFO routing for original process startup

Actual `--original` reached GameSystem::init and stopped at the old assertion that rebinding required every queued command to complete. The underlying problem was a single producer/decoder byte buffer and shared counters, so removing that assertion alone would assign old pending bytes to the wrong FIFO.

Each FIFO storage range now retains its own encoded buffer and written/published/decoded/callback-completed counters. CPU selection changes only the destination of subsequent writes. GP selection changes only the stream read by the command processor at its next decode boundary. An in-flight callback completes against its captured stream; already decoded rendering stays in the existing ordered GPU command queue. Unselected pending commands remain retained until that FIFO is selected again. No bind operation drains, aborts or copies another FIFO's commands into its replacement.

SDK snapshots, logical ring addresses, watermarks and breakpoint translation read the selected stream's counters. Breakpoint binding changes invalidate its prior interrupt as before. Abort advances the selected GP stream through the existing command-epoch retirement. Writes and unpublished header patches also maintain the actual ring bytes. A newly encountered, explicitly prefilled wrapped ring is imported through its validated count and read offset. GP binding honors explicit descriptor read/write/count programming: a stale snapshot can intentionally replay its retained ring bytes; a current snapshot preserves the existing stream untouched. Decoder revisions prevent an earlier callback from publishing its old completion into a reprogrammed stream. Storage records and buffers retire only after the FIFO worker joins at shutdown. Control binding uses a native try-lock with cooperative guest CPU release on contention. It does not acquire guest CPU ownership for otherwise CPU-independent control-register queries; this preserves callback-side rearming.

Storage is keyed by base address and size, matching physical FIFO identity rather than descriptor address. The original source contract is decomp/src/RVL_SDK/gx/GXFifo.c, GXSetCPUFifo and GXSetGPFifo: CPU selection programs its write address; GP selection programs read/write/count and then links matching storage. CPU writer repositioning is supported after unread commands retire; deliberately overwriting an unread active ring remains fail-loud rather than silently changing the decoder queue. GP replay count must fit the retained ring, as old overwritten laps cannot be recovered from physical storage. Original process runtime validation is owned by the parent.

`compile.json` records isolated compilation of both production TUs and the existing FIFO test TU before the final control-lock correction. The fresh shared build and actual focused run are the final validation (`build.json`, `run.json`): 17/17 existing FIFO breakpoint tests pass, including both new cases; binary SHA256 `58f9a1cc42b51321feb93ffa63e3f361c24a00260b102bcdd168602d316d3fa2`. The first focused run exposed guest-CPU acquisition during a callback-side query; the final lock correction is covered by the same existing callback-rearm case. Two cases were added to the existing breakpoint fixture because switching producer/consumer state is the new behavior: independent pending rings retain separate counts and resume the correct cursor; a prefilled wrapped ring starts and ends at its authored offsets and explicitly replays when its old descriptor is reprogrammed.
