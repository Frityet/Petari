# NPC source wrapper and original joint controller review

The removed wrapper had three token substitutions. `mModelManager` became a helper returning the same actual public LiveActor member; `mSpine` became a private-member friend bridge even though the actual field is now public. Both substitutions can simply disappear. The third substitution discarded the supplied member-function pointer and replaced the original generic joint delegator with an NPC-specific throwing provider. Restoring the generic template and qualifying `&NPCActor::calcJointScale` preserves the intended native member-function type and actual original behavior. Missing declaration dependencies should be supplied by normal includes, not an include-the-cpp wrapper. Root owns the direct-source build selection and removal of the three duplicate providers.

The actual native J3D resource graph already contains J3DModel, J3DMtxBuffer, named/indexed J3DJoint lookup and original-width-independent callback/userdata fields. J3DJointCompat.cpp::recursiveCalc calculates the joint, snapshots its callback, invokes phase0, visits children, restores incoming traversal state, invokes phase1 and visits siblings. JointController phase0 copies accepted edits into both animation storage and current traversal matrix; phase1 writes only animation storage and clears the callback/userdata. Thus accepted edits reach descendants without changing siblings; post edits do not propagate into child traversal. LiveActor::calcAnmMtx calls the NPC's virtual calcAndSetBaseMtx immediately before complete ModelManager::calcAnim, so per-instance registration is consumed during that actor's traversal even when resource joints are shared. No material lifecycle blocker was identified for this ordinary sequential route. A real-resource test remains necessary to prove the newly activated call chain rather than relying on direct virtual calls.

New tests/OriginalJointControllerTests.cpp supplies that proof scope: actual SDK tree/matrix/model structures; all four pre/post acceptance combinations, discarded scratch writes for false results, null delegated hooks, nonstandard phases, callback clearing and repeated traversal; actual two Tico-backed NPCActors using complete ModelManager owners and shared resource joint identity with distinct matrix buffers. It calls the normal LiveActor::calcAnmMtx -> NPC registration -> original calcJointScale route and checks both actors' matrices across two scene lifetimes. The test fixture explicitly supplies actual AnimScaleController/delegator input and does not claim full NPC initialize/talk/reaction readiness. The real resource group requires SMGPC_REAL_DISC and reports a skip separately if absent.
