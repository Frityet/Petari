# Third chase: authored crater recovery boundary

This is a read-only diagnosis of trace frames7000–10000 from `final2-route-actors.jsonl`, supported by the screenshot `final2-third-chase-ui.png`. No production code, process, controller input, or build was changed for this analysis.

The authored `CollisionBlocker` actors do not explain the stall. Their original implementation owns an eye sensor and sends the player a push message; it does not create map collision parts (`src/Game/MapObj/CollisionBlocker.cpp:12–41`). All seven blockers in HeavensDoorMysteriousZone appear through switch1015 and have radius50–150. Applying the actual scene's captured child-zone matrix to the original placement rows puts the closest blocker, l_id94,804.57 units from Mario at the nearest sampled point, with a sensor radius50. The remaining zone blockers are farther than1360 units; the root-zone blocker is more than23000 units away. The actor records themselves were not included in the selected runtime trace, so these are authored position calculations, not direct sensor captures.

There is a separate original `PullBackCylinder`, common AreaObjInfo l_id6, at the crater. It is recorded as supported in this exact run's placement inventory. Its world origin is approximately `(13894.748,-10278.820,7627.570)`, radius450 and height450. `Mario::updateCubeCode` first checks PullBackCube, then PullBackCylinder, and calls `doRecovery()` when one contains Mario (`src/Game/Player/MarioCollision.cpp:2047–2059`). `Mario::doRecovery` selects either the original recovery state or the recovery warp toward the last safe position (`src/Game/Player/MarioRecovery.cpp:8–45`). Status19 denotes both Recovery and Warp (`MarioState.hpp:25–27`).

The offline reconstruction follows original JMap zone/local composition, Euler extraction, and `AreaFormCylinder::calcDir`'s three degree-table rotations. Unlike `makeMtxRotate`, those temporary rotation matrices have opposite sine signs. Reconstructing the cylinder against original `Mario::mPosition` finds50 of301 sampled frames inside its bounds; every one records status19. This refines the initial51-sample estimate, which used the actor position and short-angle approximation. It is consistent with repeatedly steering into the authored recovery volume. The trace is sampled every10frames after update, so this does not capture the exact containment branch or prove bit-exact float parity.

The live rabbit Binder contacts reference host722, including prism4893 near `(12820,-10775,7539)`, with face feature1, depth around1.3–1.8 and no wall/roof in the examined interval. Mario's stored ground polygon references the same host near prism2081/2084. That field is cached `mGroundPolygon` (`OriginalProcessTrace.cpp:123`), so it must not be treated as a current-frame physical contact during recovery. Host722's own actor record was not in the selected trace; this analysis does not claim an independently verified authored-name mapping.

The parent operator subsequently supplied only an ordinary rightward stick sidestep at frames9840–10000. It reported the third catch at10480 and postcatch dialogue at10970, without a source change. This supports a navigation/hazard explanation for the stall, and supplies no evidence of a CollisionBlocker or KCL compatibility defect. It does not establish all terrain parity or final Rosalina completion.

One unrelated source drift was observed: native CollisionBlocker uses `50*mScale.y`, whereas current canonical decomp uses `50*mScale.x`. All eight authored Gateway blocker rows have equal x/y/z scale, so the distinction cannot explain this scene. Retail instruction provenance for that difference was not investigated in this bounded diagnostic and no code was changed.
