# Independent Demo owner review

Read-only review of the round 7 working tree against HEAD `0f8bc440af14cbc62ebaf26f221124eae447ec03`, including the deleted `DemoDirectorOwnership.cpp`. No production edits or builds were performed. This note supersedes the Demo paragraph in `lifecycle-review.md`, which described the earlier adapter-backed state.

No concrete correctness blocker was found in the reviewed ownership migration.

- `DemoExecutor` now owns its seven concrete keepers, talk animation controllers, and private stage-switch controller/IDs. `DemoCastGroup` owns its separately allocated `mInfo`. The deleted adapter previously reclaimed precisely those allocations. The executor's sheet vector contains borrowed Wipe/Sound pointers and does not delete them again; the Time keeper's subpart pointer aliases its main array and is not independently deleted.
- The Action keeper's pointer array is zero-initialized before any element construction. The ActionInfo constructor initializes all three allocation pointers before allocating and cleans partial allocations on exceptions. Camera records initialize generated-name and camera-info pointers before decoding, so `delete[]` safely visits incomplete records. Player/SubPart/Time constructors initialize their array pointers and reclaim their arrays on exceptions. Each keeper's parser stays alive through its record cleanup, then its unique owner detaches. Sound/Wipe's record destructors are trivial; their base AssignableArray owns only the record storage.
- `DemoDirector` initializes all members before allocating children. Both the destructor and constructor failure cleanup null its request/simple pointers before deleting them. The request holder deletes a proxy NameObj, which reenters NameObj retirement; the registry's callback therefore sees null fields instead of a partially destroyed request holder. Cast group holders and member groups remain separately registered NameObjs and are not deleted twice by the director/group destructors.
- `DemoExecutor::releaseNativeReference` preserves the removed adapter's compaction behavior for actor lists, talk-message references, talk controllers, camera targets, action casts/functors, and the starter reference. Removed owning pointers are deleted once and vacated slots are cleared, so later executor cleanup does not repeat their deletion. Simple-cast lists and request queues similarly preserve the adapter's order and reset matching records. The request queue intentionally handles NameObj-derived fields; NerveExecutor is a separate hierarchy, as it was in the adapter.
- The actual registry scan skips the retiring NameObj. Its new callbacks do not invalidate the NameObj map with the concrete production child types: DemoTalkAnimCtrl derives from NerveExecutor, whose Spine is not a NameObj; ActorCameraInfo is not a NameObj; current production FunctorBase implementations own only pointer/scalar callable captures. The only NameObj child destroyed by the reviewed owner paths is the request proxy, covered by the director nulling described above.
- No remaining source or test references to the removed DemoDirectorOwnership API were found. Original start/update/end behavior is unchanged by these additions; the diff adds native ownership, partial-allocation cleanup, and borrowed-reference retirement.

This is a static lifetime review, not runtime teardown validation. It covers failures after parser construction hands a parser to a keeper. Existing allocation-failure behavior inside shared parser creation helpers and broader stage-switch listener retirement were not changed by this patch and were not exhaustively tested here. Root owns integrated Gateway and focused-test validation.
