# Mounted layout resource startup boundary

The production `--original` process reached `GameSystem::init` and the original ErrorMessageWindow. Its archive and original LayoutHolder had already been published from `/Memory/ErrorMessageWindow.arc`. The native LayoutManager ignored its filename-conversion flag and constructed a LayoutRuntime which looked only through RuntimeContext or a physical archive filename. Genuine startup installs neither of those paths for the embedded archive, so the native pane owner received an empty layout.

The existing ResourceHolderService now applies the original manager's initial case-folded basename-hash lookup before resolving a DVD filename. This returns the actual previously registered holder for embedded and stationed archives. LayoutManager applies the original optional aspect/replacement filename conversion, appends `.arc`, calls the existing original MR factory, and passes a retained lease on that holder into LayoutRuntime. The layout reads that owner's already-parsed archive, uses basename resource lookup as the original resource tables do, and retains the archive and owning heap until native panes/materials retire. It does not reopen/copy the archive or create an additional resource owner. Actual TextBoxes resolve their font through LayoutHolder::GetFont, including the genuine process's embedded font. Explicit standalone archive construction remains available.

Original conventions were checked against `decomp/src/Game/System/ResourceHolderManager.cpp` (`createAndAddInner`, `add`, `find`) and the retail LayoutManager constructor/initArc at 0x803683BC/0x8036948C in `notes/gateway-audit-20260907/restoration/retail/asm/Game/Screen/LayoutManager.s`. No Game source or reference file changed. This fixes resource selection and ownership for the existing native layout record bridge; it does not claim that bridge is the complete original LayoutManager implementation. Process font pointers keep their original borrowed lifetime, and the actual font owner must outlive its text users.

Required validation: all four affected translation units compile successfully with the project's native flags (`native-proof.json`). No extra subsystem tests were added or run. Root owns the next production build/run; startup progress beyond this boundary is pending that run. Per-file patches are relative to captured starting files, preserving the earlier uncommitted integration work.
