# SDK and original input-owner integration review

Reviewed the parent's SDK/client integration in `aurora/lib/wpad.cpp`, `aurora/include/aurora/wpad.hpp`, `src/compat/WPadOwnership.cpp/.hpp`, and `src/compat/OriginalWPadHolder.cpp`. This follow-up changed only fixtures and notes; the parent owns production fixes and builds.

Two material issues were found and corrected by the parent:

1. **Pending information buffers escaped their client lifetime during dispatch.** The first implementation removed all raw `WPADInfo*` pointers from the client before invoking connection callbacks. If a callback retired its client and information buffer, the dispatcher subsequently wrote into freed memory. `CallbackRetirementProbe.cpp` reproduces this using the actual unmodified SDK implementation; its only stand-ins are unused motor-output functions required to link the standalone SDK TU. ASan reports a heap-use-after-free write at the old `wpad.cpp:130`, with the freeing callback at line115. The same fixture freshly compiled after the parent's fix exits0 under ASan and UBSan. The fixed dispatcher captures request identities, keeps borrowed buffers in the active/suspended client state, and checks the client generation after each arbitrary callback. Requests queued by callbacks remain deferred, and temporary client suspension no longer detaches the outer request's storage.
2. **Nested ownership restored gameplay rumble unconditionally.** Both normal teardown and failed construction re-registered each outer `_18` object, losing an outer `_1C` menu selection. The fixed owner snapshots the actual two callback-table entries before construction and restores those exact entries, including null. Successful restoration calls `registInstance` on the saved actual object, retaining its original motor behavior. Private static access stays in native ownership infrastructure; the Game header is unchanged.

The sanitizer commands, baseline and fixed source/header hashes, and exact exit results are retained in `callback-retirement-proof.json` and `callback-retirement-fixed-proof.json`, with corresponding logs. The initial run fails with ASan; the fixed build and runtime both exit0. Leak detection is explicitly disabled, so this is a buffer lifetime proof rather than a leak-freedom claim.

The remaining reviewed startup and normal teardown ordering is coherent for the current owning-thread contract:

- The one-time actual WPad constructor initializes process-lifetime rumble-table storage under the host allocation domain. Its temporary typed children are destroyed immediately. Its constructor dependencies are static table hashing and SDK parameter setters; none require the unpublished native owner.
- The SDK client scope is constructed before the original holder and temporarily saves an outer client's callbacks, pending information buffer, and allocator hooks. The new holder's callback registrations defer delivery until `WPadOwnership` is published.
- Current `KPADInit` retains allocator callbacks but allocates no Bluetooth work buffer. Therefore it does not call `MR::allocFromWPadHeap` before owner publication. This dependency is explicit; a future SDK allocation at initialization would require an earlier allocation-domain publication seam.
- `update_samples` pumps callbacks under the retained Game allocation domain, then invokes the actual original holder's read/project/mode sequence.
- Normal teardown destroys typed Game children and four original read buffers. Current child destructors do not pump SDK callbacks; destroying the SDK client scope afterward discards its pending writes and restores the suspended outer client before the outer publication is resumed. Completion writes happen only through the explicit owning-thread pump.

`tests/OriginalWPadOwnershipTests.cpp` uses actual owners and Game objects to check four120-record buffers, heap callbacks, deferred connection/extension/information delivery, battery publication, Home Button borrowed records, original extra-channel disconnection, sensor-bar setup, reset and auto-sleep calls, nested pending-request cancellation/resumption, menu rumble restoration, and construction rollback on an insufficient original heap. It also includes a deterministic callback-retirement marker test alongside the separate freed-buffer sanitizer reproduction. Syntax passes; linked runtime validation belongs to the parent's official target.

The acceleration fixture's initial linked attempt exposed a fixture error: `KPADStatus{}` intentionally defaults to `WPAD_ERR_NO_CONTROLLER`, while its synthetic successful records had set only device type and accelerometer values. The fixture now explicitly sets `WPAD_ERR_NONE` for valid individual and batched records, plus `WPAD_DEV_CORE` for the full core batch. This preserves original `MR::isDeviceFreeStyle` rejection semantics; no Game or SDK behavior was changed to accommodate the fixture.
