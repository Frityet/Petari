# Fur and Karikari link-gap audit

This is a source and original retail-object audit, not a gameplay result. Retail self-diffs are used only to decode instructions and call references; they are not evidence of a recovered-source match. No Fur implementation was changed.

## Fur requires a subsystem restoration

`MR::initFurPlayer` already delegates to `initMultiFur(actor, 0)`. The actual return is a `FurMulti*`; the native declarations correct the older decomp header's `LiveActor*` placeholder. Native FurMulti only provides the previously proved constructor and off/on draw masks. There is still no decomp FurMulti.cpp; restore those already proved bodies and the actual class declaration to decomp before additional recovery.

The missing original `initMultiFur` is 1,292 PowerPC bytes. It selects the actual scene GDDR3 heap, counts materials whose names contain the original fur marker, and only returns null when there are no such materials. Otherwise it allocates FurMulti, FogCtrl, shared dynamic material state, and one copied 0x68-byte FurParam per matching material. It resolves material-name-derived Body, Length.bti, Indirect.bti, Density.bti, and .fur.txt resources, uses the original material texture fallback when the named Body texture is absent, applies optional parameter text, calls setLayerDirect for each material, attaches the fog and dynamic state to each controller, registers all controllers, and restores the heap. These operations are visible in initMultiFur-retail.asm and the resource suffix dump.

The smallest coherent restoration includes FurMulti::setLayerDirect (484 bytes), addToManager and FurBank registration; FurCtrl construction, layer calculation, setup/clone, map generation and draw; FurDrawManager construction and registration; FurParam/DynamicFurParam parsing; the entire absent FurDrawer implementation; and missing CShader index/vertex/length-map operations. The four original objects contain 39 functions and 12,788 PowerPC bytes. Of those, 28 function bodies are absent from both native and reference sources (only 3 FurMulti, 2 FurCtrl and 6 FurShader bodies currently exist across those sources). FurDrawer currently has no header or source. CShader::setup's empty body is genuine: the retail function is exactly a return instruction, unlike its missing calc/makeIndexData/checkBorderVtx methods.

Pointer layout recovery is necessary before a native copy: the existing FurCtrl `_4` and `_8` are u32 placeholders, but initMultiFur stores a FogCtrl pointer and a shared dynamic-state pointer there. Other setup fields must be typed from their uses too; retaining Wii-width pointer placeholders would truncate native addresses. Fur shader setup also clones J3DModel data, creates index/vertex buffers, reads quantized formats and flushes generated data before J3D/GX rendering. The original fixed16/float conversion helpers and text parameter scanner providers require native selection/recovery; a successful wrapper link alone would not supply this renderer.

Existing ownership boundaries are useful: getSceneHeapGDDR3 selects the actual ResourceHolderService-owned JKRSolidHeap, and CurrentHeapRestorer selects/restores the original heap. ResourceArchiveOwner retains the real model/texture archive backing. SceneObjHolderBinding now owns its ordinary Game callback arena and typed NameObj teardown separately. FurDrawManager must be an actual scene object, with its registry and all borrowed actor/model pointers retired before those owners disappear. The original GameScene creates FurDrawManager during normal initialization (GameScene.cpp:94), before fur actor setup; the native SceneObj factory currently lacks its case. No fur-specific global lifetime or dummy draw object is warranted.

## Karikari has complete original source

The original director wrapper already tests actual SceneObj_KarikariDirector existence, then visits five registered attachment slots. For each non-null actor it calls tryHipDropRelease and unregisters that actor. This guard is original behavior; it should not be widened to skip real actors.

Karikari::tryHipDropRelease is 160 retail bytes: compute actor minus player position, remove the gravity component, set its length to 43, subtract gravity times 33, store velocity, and enter the actual DPDAttacked nerve. The next state restores binder/shadow/gravity/sensors, starts the original animations and Touch effect, applies the original movement damping/gravity, then enters Land on ground contact. Land and its ordinary transitions retain the rest of the actor's state graph, so implementing only the first leaf or substituting an empty nerve would break recovery after release.

The entire 998-line decomp Karikari.cpp exists. Fresh Wii compilation succeeded and tryHipDropRelease, exeDPDAttacked, and applyEnvironmentInfluenceToVelocity each compare at 100%. See Karikari-wii-compile.json and Karikari-source-objdiff.json. Native syntax of that unchanged file initially reports missing stopScene, appearStarPiece and two StarPointer declarations plus TVec2::setLength; the exact command/log are saved. The smallest sensible source activation is the whole original translation unit and exact shared math/header fixes, followed by actual reachable provider closure. StarPiece emission, scene pause and secondary-pointer interaction must be supplied by their real systems if retained; this audit does not define no-op substitutes.

Karikari::init creates its original director and joins the actual group, and its existing native director source contains real slot registration/unregistration. The native SceneObj factory currently lacks KarikariDirector; scene binding and the generic actor/NameObj registries can own it once the real constructor case is restored. Its heap arrays and FixedPosition objects fit the ordinary scene domain; its pointers to live actors and player joint transforms still require normal teardown ordering. The parent approved separate Karikari restoration after this audit, while deferring the larger Fur subsystem.
