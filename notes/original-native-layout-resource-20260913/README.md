# Retained native NW4R binary resources

Actual SDK Layout::Build now normalizes packed BRLYT records, retains the converted bytes, and runs its original block walk and pane/group/material constructors. Block order, hierarchy markers, local transforms, flags, resource offsets and contents are preserved. Material conversion reuses the existing validated BrlytLayout native material records. No ISBN-specific layout graph or successful substitute parse was added.

The native text resource byte counts are u32 (existing TextBox runtime byte counts were already u32). This preserves the full original u16 byte-count range after widening UTF-16 units to native wchar_t. Each original unit, including surrogate and control-tag units, is retained individually; colors become native packed scalar values and string offsets/block sizes are rebuilt for the native TextBox record. Original logical character counts remain unchanged.

The same NativeLayoutResource owner normalizes BRLAN headers, tag/share blocks, content/info/target offset tables, and step/Hermite key records. AnimResource retains the complete converted file. Original Layout-created transforms retain that same owner, preserving borrowed record lifetime; separately decoded resources compare their original source identity when finding an existing animation link. Unknown/empty curve encodings fail explicitly. The original SDK still evaluates and applies each animation. Direct SetResource(native block, ...) retains its original caller-owned input contract.

ArcResourceAccessor checks declared binary file sizes against actual archive-entry bounds and converts packed TPL resources with the existing TplTextureData/make_tex_map path. Native ResourceAccessor now exposes texture backing ownership to Material; texture-pattern animations retain and transfer that ownership when changing images. This keeps texture/palette bytes alive after accessor retirement. Accessor reattachment releases its cache without invalidating material leases. Existing Nw4rLayoutRecords uses the same accessor method, removing its separate post-construction texture-state assignment loop. No fabricated TPL descriptor or truncated pointer is returned.

The void-pointer Layout/AnimResource API still requires the caller to supply a complete readable resource file, as on Wii; its header supplies the byte span. ARC additionally validates that span against the actual file length. Font parsing remains the existing native ResFont boundary. Existing GetSignatureInt had already been corrected by the startup closure and was not edited here.

All seven affected native implementation TUs compile (compile.json). No tests, shared builds, runtime rendering or gameplay success are claimed. Production files frozen for root's immediate app build. New shared source: src/layout/NativeLayoutResource.cpp. The twelve-file source manifest records this snapshot; shared source files also contain earlier owner/source restoration work which is preserved.

Shared production compile exposed a missing direct forward declaration of HostTextureResourceState in animation.h. Added that declaration without changing ownership or behavior and refreshed the manifest. Root reruns the production build.
