# Original movement and camera integration checkpoint

The current priority is actual Mario jumping with the original CameraDirector, CameraManGame, CameraContext and stage camera selection. The preserved walking preview did not provide jumping or the complete camera system. This checkpoint is source integration, not a playable replacement demo.

StageResourceBinding now retains the selected start/path JMap tables and their zone metadata. Start enumeration follows the original recursive holder order, layer-bit order and archive entry order, including repeated zone occurrences. Rail queries retain the first matching root/immediate-child zone, use the row index for CommonPathPointInfo filenames, preserve outputs for non-camera usage, and never invent missing points. The original SceneUtil/StageDataHolder methods were recovered first in decomp and compared to RMGK01; reviewed functions score 99.31–100 percent. Two incorrect JMapInfo return declarations are restored to the original JMapInfoIter(table, row).

Current-start camera queries use the selected scene-entry MarioNo. SceneUtil's initialize-start key is the original constant (0, 0), distinct from that selection. The scene's real temporary-data owner initializes its restart key from this constant. Both native host scenes publish their actual transition from initialization to ordinary gameplay; introduction predicates read that scene phase, not camera flags. Actual opening/starter scene execution remains separate unfinished work.

Scenario animation resources are loaded from the root archive, validated through the existing CANM/CKAN decoder and retained as aligned native-endian blocks. Original CameraAnim reads those fields directly. Stage placement resolution now sends only BCAM files from the camera directory to BCSV parsing: an EggStarGalaxy CANM was previously incorrectly parsed as a table. The original BCAM archive identities and borrowed strings retain their existing lifetime behavior.

The obsolete walking-only static-library target is removed. Its 18 already-compiled Player translation units now belong to the normal Game archive, along with restored sensor, defensive-message, clap and rush sources. This makes original player/camera methods available to all scenes and tests. No custom jump trajectory or camera coefficients were introduced. The other native leaves in this checkpoint forward the original rail, event-flag/explanation, HUD and controller-speaker behavior; setNan preserves retail 0xffffffff component bits without strict-aliasing violations.

Validation: stage resource build/run passed with the actual local Korean RVZ. Gateway exposes 42 camera rows, 10 start rows and 3 root rails; Egg Star exposes 111 camera rows, 25 starts and 16 root rails. Root rails in those fixtures are not camera rails; synthetic fixtures separately exercise camera filtering, repeated/nested zones, non-sequential rail IDs, borrowed table lifetime, missing points and stable row/ID lookup identities. Egg Star's scenario animation decodes and keeps stable native storage. The original scene-counter owner build/run passed, including real Game-heap ownership, typed teardown, 64 original flag records, original restart defaults, nested sessions and phase predicates.

The combined showcase compiles and archives successfully, then fails to link with 37 unresolved functions listed in checkpoint-undefined.json. The sensor fixture now links up to four StarPointer queries and ChipGroup::noticeEndCompleteDemo; it has not run. CameraDirector's new component fixture is syntax-checked only. Full jumping, original camera movement in Gateway, the rabbit chase and Rosalina are not yet validated. The confirmed Mario PPC/native bitfield-layout mismatch is an additional architecture blocker recorded in the Player checkpoint; it is not fixed here.
