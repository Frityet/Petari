# CP932 consolidation into TextEncoding (read-only plan)

The three compat files can be removed without changing Game expressions or adding a replacement wrapper header. `resource/TextEncoding.hpp` already owns host UTF-8 / authored CP932 conversion. Absorb the existing constexpr literal implementation directly there, beside its runtime conversion declarations; keep `CP932(text)` as the public literal API with `smgpc::resource::cp932` implementation namespace. Delete all `smgpc::compat::cp932` spelling and the old include path rather than supplying aliases. No caller refers directly to that namespace.

## Exact implementation

1. Merge `src/compat/Cp932Literal.hpp` implementation into `src/resource/TextEncoding.hpp`, including cstddef/cstdint and the mapping data include. Keep `Utf8Literal`, strict scalar decoder, binary-search mapping lookup, `EncodedBytes`, and `EncodedLiteral::inline static constexpr value` unchanged apart from their owning namespace. This preserves array lvalues, exact extent, embedded NULs, adjacent-literal preprocessing, escaped/raw/u8 input support, and shared static storage across translation units. Do not replace any expression with runtime `encode_cp932` or a temporary string.
2. Place the frozen data at `src/resource/detail/Cp932Table.hpp` and `src/resource/detail/Cp932Mapping.tsv`. Only the table namespace changes. Preserve TSV bytes and table entries exactly. Live inspection confirms 9,280 non-ASCII entries and TSV SHA-256 `46778ae55afa614d3ece7e4f7160d9f1205626f09a461e6d7a933b57b582d600`. Delete all three old compat files. These are data alongside the existing codec, not a new standalone compatibility service.
3. Mechanically replace `compat/Cp932Literal.hpp` includes with `resource/TextEncoding.hpp`: currently 719 Game files (671 cpp, 48 hpp), plus six direct test consumers (`Cp932LiteralTests`, OriginalProcessPlacementTransform/PunchingKinoko/TrampleJump/WarpPod, OriginalSensorMatrix). Preserve every other byte and all `CP932(...)` expressions.
4. Update path references in `tests/test_cp932_literals.py` (table/TSV paths and generated source includes), `scripts/source_mirror_encoding.lua`, `tests/SourceMirrorEncoding.hpp`, `tests/SourceMirrorEncodingTests.cpp` and `.lua`, and README's original-string-encoding section. The source-normalization helpers must continue accepting only one exact leading encoding include and literal-only wrappers; update that spelling, do not relax their other rejection cases. These account for the remaining four test consumers and one script (730 source/test/script files with old header path total).

## Build and scope

The project already compiles C++23. There is no CP932 build provider, generation rule, or xmake dependency to migrate. `TextEncoding.hpp` remains self-contained for the existing standalone compiler fixture: its unused runtime declarations do not require linking TextEncoding.cpp. Existing CP932 and source-mirror tests need path changes only; no new cases or frameworks are necessary. The large edit count is mechanical include spelling, not Game behavior.

Keep `TextEncoding.cpp` runtime platform codecs unchanged in this bounded batch. Its Windows/iconv conversion policies are separate runtime behavior; folding the literal API into their existing owner does not require changing them. In particular, do not opportunistically switch literal mapping to iconv/Shift-JIS or claim that platform runtime conversion now shares the frozen table. Existing runtime tests remain available but are outside this planned change.
