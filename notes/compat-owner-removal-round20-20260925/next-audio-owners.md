# Next audio ownership removal (read-only, 2026-09-25)

Recommendation: retire the preview PCM-to-Game bridge and consolidate the explicitly disabled original-process audio state in one coordinated batch. Audio is out of scope for the demo; restoring DSP playback is not a prerequisite. There are **24 remaining audio-related compat files** (including `compat/jaudio/`), not independent platform shims. Do not rename these classes into another directory.

## 1. Fastest substantial closure: remove alternate playback plus facade

Delete `compat/AudioFacadeCompat.{cpp,hpp}`, `NativePcmSound.{cpp,hpp}`, `JaiStreamPlayback.{cpp,hpp}`, `JAudioSoundParameterSemantics.{cpp,hpp}`, and `jaudio/JasStreamPcmBackend.{cpp,hpp}` (10 files). Remove `runtime/JAudioPlaybackService.{cpp,hpp}` and its RuntimeContext constructor injection, frame/shutdown calls, start/stop/query APIs; remove obsolete AudioEventService state from RuntimeServices and its ParityTrace serialization if nothing outside that preview branch remains. The current original process uses AudSystemWrapper's disabled backend and never requires these PCM voices. Retain Aurora's general mixer/STRM/BAA decoders: `aurora/{include/aurora,lib}/{audio,j_audio_stream,j_audio_sound_archive}.*` are reusable SDK/resource facilities, not Game policy.

`AudioFacadeCompat.cpp` is 869 lines of alternate implementations for seven complete donor owners: enable existing `Game/AudioLib/{AudFader,AudTrackController,AudBgm,AudBgmKeeper,AudBgmMgr,AudBgmRhythmStrategy,AudWrap}.cpp`. It owns a global `s_bgm_manager`, thread-local event override, duplicate BGM lane synchronization, and many throwing rhythm methods. Restore original owner state rather than preserving that global. `AudBgmVolumeController.cpp` is already active.

Required integration, not a blind enable: donor AudWrap dereferences `AudSystem::msBasic`, which is currently deliberately absent. In the disabled configuration, direct Game owner entry points must return absent handles/no output and keep necessary initialization/reset completion; they cannot simply use unguarded donor getters. The actual AudSystemWrapper can own the original BGM manager alongside its existing audio resource lifecycle, or the actual AudSystem must be constructed coherently. Do not manufacture an AudSystem pointer solely to satisfy getters. This ownership decision must be shared with item 2 before edits. Restore donor BGM/fader/keeper algorithms, with explicit disabled-output boundaries on the actual owners, instead of transplanting the facade implementations.

The two-ID table in `JAudioSoundParameterSemantics.cpp` (0x6001a/0x6001b) is especially obsolete: all three complete `AudSoundObject_{Kawamura,Takezawa,Gohara}.cpp` donors now exist. Deleting preview playback deletes this whitelist; future real playback must call the original modifiers.
