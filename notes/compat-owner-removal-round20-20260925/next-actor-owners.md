# Remaining actor registry owner split

After dead API pruning, remaining registry code has two distinct real owners and a few borrow-retirement sweeps. Split the work at those boundaries; do not transfer the map or state structs to a renamed service.

LiveActor can own the existing shared ModelManager directly (also borrowed by actual DrawBufferExecuter and MarioAnimator). Its unique Spine, RailRider, Binder, ActorLightCtrl, StageSwitchCtrl, LodCtrl, animation helpers and AudAnmSoundObject belong on the actor, alongside its already-owned CollisionParts vector. Keep the retained audio domain through sound destruction. Original raw fields remain observations of those owners. Replace existing initialization shim calls with real class methods and idempotent native retirement, used by actual Scene/SceneObjHolder/process prepasses. Runtime/StarPointer references retire before model/target destruction. Preserve clipping holder/group backreference invalidation.

NameObj needs native identity generation and claimed ownership on the actual object. A live intrusive object list maintained by NameObj construction/retirement can replace the allocating unordered_map, including objects constructed before a holder is selected. Search that list for address/generation queries without dereferencing stale caller pointers. Construction markers remain needed for actual scene and constructor-rollback ownership; preserve reverse-order retirement without allocating while children destruct. Original NameObjHolder still owns registration/placement arrays and must not be replaced by the intrusive lifetime list. Original names stay borrowed and movement flags keep their original deferred sync semantics.

Borrow invalidation belongs to actual borrowers. Existing TalkDirector, DemoDirector/Executor and BaseMatrixFollowTargetHolder already expose releaseNativeReference(NameObj*) methods. A native virtual NameObj retirement notification could let those owners, NameObjGroup and LiveActorGroupArray clear real borrows without registry dynamic_cast policy. Inspect reentrancy before changing traversal. HitSensorKeeper must invalidate taking/taken/contact pointers in other live keepers and pending MsgSharedGroup sender pointers before sensor deletion; this cannot be dropped with the map. Actual ClippingActorHolder and ClippingGroupHolder destructors must invalidate live actor borrows.

There are about 70 direct header consumers across source/fixtures. Remove the old compat include and all APIs together when the two owner lanes are integrated. Update existing fixture calls mechanically or drop only obsolete mirror-state contracts; no new fixtures or suite expansion. Keep the one-build/one-opening-smoke validation boundary.
