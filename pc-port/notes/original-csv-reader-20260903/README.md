# Original CSV helpers over retained archive data

Recovered `MR::getCsvDataF32`, `getCsvDataBool`, and `getCsvDataVec` in root `src/Game/Util/ObjUtil.cpp`, then copied fourteen complete original helpers into native `compat/OriginalCsvReader.cpp`. The original Game controllers and FixedPosition can use their ordinary table interfaces without a replacement animation-name policy.

Run `python3 pc-port/notes/original-csv-reader-20260903/verify-original.py` from the repository root. Full root ObjUtil compiles with the configured original GC3.0a3 compiler. Fourteen existing/recovered helpers match the original object at 100%; vector reading has the same 192 instruction bytes and references after resolving three generated labels to the verified original `%sX`, `%sY`, `%sZ` strings. The two recovered scalar methods have 256 identical relocation-normalized bytes. Durable details are in source-evidence.json.

The archive-name `createCsvParser` overload remains inactive because original ResourceHolderManager is not active. Its original implementation intentionally does not forward the extra variadic arguments; the complete method matches retail at 100%, so it has not been rewritten. Holder and actor overloads preserve their full original bodies, including the 256-byte filename format buffer and caller-supplied defaults when fields are missing. Vector/color APIs are not conflated: the color helper is still unrecovered.

Raw archive entries now register their immutable byte bounds and source ownership. The actual JMapInfo::attach decides when those bytes are a table; parsing is deferred and shared through std::call_once. No file extension or actor name triggers an invented schema. Eager typed `.banmt` resources retain their prior behavior. Conflicting identities/extent or owners are rejected, malformed raw data is rejected only when explicitly attached, and decoded readers retain their own table/string storage after archive retirement. Registry locks are released before parsing and source retirement.

Native parser metadata requires a destructor even where the original Game code relied on raw heap reclamation. The companion NativeJkrDisposer boundary connects that metadata to the actual JKR heap disposal list, with independent registration for copied/moved objects and host-owned nested metadata. It preserves the original callers that allocate temporary parsers without individual deletion. See the separate JMap heap-lifetime notes for its evidence.

Validation passed in the shared native build: five actual-heap lifetime groups, ten deferred JMap groups, five real-disc ResourceHolder groups, and rebuilt title/Gateway smokes (two/five rendered frames). Commands and results are in `../jmap-parser-lifetime-20260903/validation.md`. The focused ResourceHolder test uses a raw file without a recognized table extension, exercises the literal variadic parser and scalar/vector helpers, missing defaults, masked bools, empty strings, raw malformed attachment, and archive-to-reader lifetime. Deferred identity tests exercise concurrent first reads and source retirement. This is control-data and lifetime activation; original actor animation/scene draw ownership still needs the atomic consumer migration before jumping can be claimed.

The actor CSV overload is linked through two complete original resource-access methods in `compat/OriginalActorResource.cpp`, with root-identical ModelManager.hpp. They read only the actual mModelManager and its original resource ownership; they do not adapt the old LiveActorModel renderer. Full ModelManager/actor-provider publication will remove this extraction translation unit and supply the same methods from their full original source units.
