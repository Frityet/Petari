# Retained original J3D joint resource component

`resource/J3dJointData.{hpp,cpp}` owns the native INF1/JNT1/EVP1/DRW1 data needed by a real `J3DModelData`. It reads retained authoritative BMD2/BMD3/BDL4 bytes directly; the renderer's lossy summaries are not factory inputs. The constructor copies all referenced data, so the source archive can be retired afterward.

The narrow API is `J3dJointData(span<const uint8_t>, uint32_t load_flags = 0)` followed by one `attach_to(J3DModelData&)`. It never constructs or returns a ModelData. The complete resource owner must retain this component through model lifetime, build the material/shape/vertex/texture tables, validate their hierarchy references, and perform original finalization. Moving the component preserves all attached addresses. Reattaching or overwriting an existing joint tree throws before mutation. No production resource or renderer is switched to a partial model.

## Original correspondence

- `J3DModelLoader::readInformation` supplies combined load/INF flags, the original Basic/Softimage/Maya no-animation calculator, packet and vertex counts, and the complete typed INF hierarchy. Material/shape commands remain in the hierarchy. No links are synthesized.
- `J3DJointFactory::create` supplies actual `J3DJoint` construction, logical joint numbers and remapped authored SRT/bounds. Retail `0x80440674/78` loads kind as u16 and stores its low byte; `0x80440690/94` copies compensation as a byte. `0x80440740/48` changes only its `0xff` sentinel to zero. The original factory header labels the stored field `bool`, which is unsuitable for directly reinterpreting arbitrary resource bytes on the host; the bounded decoder preserves the actual byte semantics without casting file bytes to that header.
- `J3DModelLoader::readEnvelop` supplies flattened mix counts/indices/weights and the inverse matrix table. There is no inverse-table count in EVP1. The component retains every complete matrix readable between the stored pointer and block end, including matrices not used by the current envelopes. Every referenced matrix must be present; nothing is silently dropped.
- Retail `readDraw` at `0x8043ea68` subtracts the envelope count present when DRW1 is encountered from the serialized draw count, then scans for the first raw flag exactly equal to 1. Native construction preserves that file-order dependency, all raw flag bytes and the full serialized index array. It does not use the summary's boolean flag or serialized count as the native entry count.
- `JUTNameTab` receives an owned, aligned native-endian ResNTAB header/entry table, preserving original key codes, string offsets, unknown header field and bytes. The actual JUTNameTab methods are supplied by the parallel original resource work. Missing name tables remain absent. The original loader accepts the stored name count independently of joint count, and original `JUTNameTab::getName` returns null for an index beyond that count; this component preserves that behavior. A complete-owner API that promises a name for every joint must establish that stronger caller precondition itself.
- `J3DJointTree::findImportantMtxIndex` is imported unchanged into `compat/J3DJointTreeCompat.cpp`. The component allocates its original output extent but does not invoke finalization. The tests explicitly call the original method and check greatest-weight selection and first-entry tie behavior.

`verify-source.py` verifies the unchanged helper body, compiles the root TU with the original GC 3.0a3 compiler and project flags, and checks the cited instructions against the verified RMGK01 DOL. The helper is 99.888885% objdiff over 180 retail bytes. This is not an original-compiler matching claim for the host byte decoder. `source-evidence.json` records the result; raw compiler/disassembly artifacts remain under `build/original-j3d-joint-resource-20260903/`.

## Bounds and accepted data

The component validates the declared file/block bounds and required construction sections, rejects duplicate retained section identities, and checks every table and referenced joint. The original traversal must have known commands, an in-block terminator and balanced child scopes. Unsupported low-nibble matrix modes cannot produce an original calculator and are rejected. The full owner remains responsible for material/shape indices and parent/mesh availability before hierarchy linking.

The original envelope loop requires positive influence counts. Draw indices must address their actual joint or envelope table. The original draw allocation must hold the later important-index output, and count subtraction must not underflow. Strings must terminate inside their containing section. Floating point metadata and weights are copied bit for bit, including signed zero; there is no normalization, guessed bind transform, or replacement weight policy.

## Focused validation

`smg-pc-original-j3d-joint-resource-tests` contains four groups:

1. Native original joint construction, reversed remap, SRT/bounds, kind narrowing, raw compensation/ff sentinel, retained name records, complete raw draw flags, original important-index ties, source retirement, move stability and rejected reattachment.
2. All three actual original calculator types, absent names/envelopes, retained unreferenced inverse matrices, rigid important indices, and DRW-before-EVP file-order behavior.
3. Seventeen malformed resource cases covering section boundaries, remaps, modes, hierarchy commands/scopes, empty envelopes, missing inverse matrices, count underflow, important-index allocation, draw references and names.
4. The actual `Mario.arc/mario.bdl` resource through DVD/RARC, checking every joint transform/bound, original names, envelope fields, inverse matrices and all serialized draw records. Original important-index selection and post-archive lifetime are exercised.

Independent extraction from the supplied RMGK01 disc establishes `mario.bdl`: 30 joints, 13 envelopes, 48 serialized draw records, 35 native draw entries, 22 full-weight entries and 30 inverse matrices. The 22 rigid plus 13 selected envelope indices exactly fill the original 35-entry output allocation. Compact metadata is in `retail-resource-metadata.json`; no game resource bytes are checked in.

Both native source and test pass isolated clang syntax probes. The parent reports the initial integrated shared target passed all four groups with the actual disc enabled; fresh title and Gateway smoke checks also passed. The final DRW-before-EVP regression was added after that binary, so `verify-native.py` separately compiles the final test, JointData and complete JointTreeCompat into isolated objects and links them against the unchanged prior frozen native archives. That final executable passes all four groups with the actual Mario resource enabled. `native-evidence.json` records exact source, archive and executable hashes, and `native-final.log` records its output. No shared build or GPU work occurs in that verifier. Set `SMGPC_REAL_DISC='../Super Mario Wii - Galaxy Adventure (Korea).rvz'` from `pc-port` to enable the actual-resource group. This fixture attaches only the component to intentionally unfinalized test ModelData; it makes no claim of a complete Mario model or activated original Mario animation owner.
