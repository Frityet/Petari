# Bounded owner/provider review

The original `J3DModel` constructor → `calc` → `viewCalc` path uses the real embedded vertex buffer and actual matrix buffer. Matrix tree, per-joint arrays and shared default constants retain their declared types. The joint-only regression creates genuine model data, supplies an original Basic calculator and restores global J3D state after use; it does not construct fake virtual objects or treat undecoded material data as complete. No additional production defect was found in this bounded path.

One fixture cleanup was corrected before freeze: `new (0x20) Mtx[...]`/`Mtx33[...]` storage now uses the matching alignment-placement delete overload. Pointer tables and animation/flag allocations still use ordinary `delete[]`. The original empty destructors do not assume ownership. The fixture recognizes the shared no-use arrays, so the allocation-flag cases do not free static storage. Production/native owners added later must also account for material bump arrays and shared display-list ownership, which the intentionally joint-only fixture does not exercise.

The apparently surprising `static BOOL sInterruptFlag = OSDisableInterrupts()` in `J3DModelData::indexToPtr` was inspected against retail at `0x80431AF0`: the binary really does contain a static-initialization guard and one-time interrupt-disable call, followed by scheduler calls and restoring the saved flag. This existing source behavior should not be changed into a per-call local as a speculative cleanup. The read-only disassembly is in `build/original-j3d-mtx-buffer-20260903/retail-indexToPtr.asm`.

The full original `J3DModel` virtual methods are available as dependency closure; this review and matrix regression do not prove loaded material/shape rendering, positive bump data, CPU skinning, display-list generation, or new resource decoding. The original resource preconditions and empty-destructor ownership boundaries remain explicit. No shared xmake build was run by this review.
