# Independent review of updateGravityVec

Reviewed the recovered root `MarioActor::updateGravityVec` against `build/mario-gravity-restoration-20260903/update_gravity.annotated.asm` and the verified RMGK01 DOL (SHA1 `25c5959534b3c21246c6c7e42021b916b41fb578`). This was a read-only source/binary review; no Game edits, builds or runtime experiments were performed by the reviewer.

## Concrete finding

The recovered animation argument was **`"スケートジャンプ2"`**, but retail requests **`"ショートジャンプ"`**. Instructions at `0x802B9D24` and `0x802B9D2C` form the pointer from `lis r4,0x805C` followed by the **signed** offset `-0x7928`, yielding **`0x805B86D8`**, not `0x805C86D8`. The bytes at the correct address are `83568387815b83678357838383938376`, which decode as `ショートジャンプ` in Shift-JIS. This argument error survives a branch/call-graph comparison and would select a different animation group after a large gravity change during a jump.

The author confirmed the address-carry mistake and corrected both the root literal and the relocation oracle. The reviewer reread both files to confirm the corrected string and `0x805B86D8` address; compiler verification remains the author's task. The review found no other concrete semantic defect in the branches and expressions below. The function SHA256 at initial review, before that correction, was `c4f65ce878e637df32f0354b8f8c4ff65f804be296ce5117f1a393aa132394ea` (signature through closing brace and its following newline).

## Explicitly checked behavior

- **Input flags and gravity samples (`0x802B9AB8–0x802B9C88`):** position gravity always samples `mPosition`; `usePosition=false` additionally samples `_2A0`, while true copies the first result. The forward sample is `mPosition + mFrontVec * 100`, with no GravityInfo output. The `_370` comparison uses position minus forward gravity. Foo special gravity replaces both samples. For disagreeing directions, the sample with the greater dot product against the previous air-gravity vector wins. Either zero vector suppresses the change angle.
- **Reset and jump response (`0x802B9C88–0x802B9EE4`):** `isReset=true` clears `_334` and bypasses the angle/jump response. Otherwise a nonzero `_334` reuses `_24C`. The thresholds are inclusive 30°, 72° and 120°. `_10._1A` is the retail `0x20` mask; `_10.turning` is `0x10000000`. `_37` selects `0x100` in the second movement word. At 120° or when `_37` is clear, the code removes the gravity component and halves the remaining jump vector. The other branch retains 0.75 of both the perpendicular and projected components, with the projection added back using the original gravity direction. `_2E0` is negated only when `_37` is clear.
- **Basis and zero-gravity fallback (`0x802B9EE4–0x802BA0DC`):** the axis helper takes old `_24C` then new gravity. Rotation transforms `_258` without translation; cross products are `_258 × gravity`, then `gravity × side`. The second cross runs when `normalizeOrZero` returns false, which correctly means a nonzero normalized side. Entering gravity uses `calcBaseFrontVec(-gravity)`; remaining in zero gravity uses Mario `_1FC`. `_24C` stores the sampled vector before zero-gravity fallback. Grounded fallback is `-_368`; airborne fallback is prior `_240`. Bee adjustment precedes `setGravityVec` and storage into `_240`; requested ground-normal reset uses the negative final gravity.
- **Offset calculation (`0x802BA0E4–0x802BA254`):** the blend's first vector is always `mHeadVec`; its second is `_380` at `0.5 * _984` for draw flag `_F`, otherwise `_368` at `_984`. The normal height is 70, reduced to 50 by movement `_A`, and the grounded flag `_1` directly assigns `up * height`. The airborne conditional is `_10._23 || actor._934`. Both airborne paths target `-_240 * 70`; the conditional path uses 0.1 when `_334` is nonzero or polygon angle is **at least 59°**, otherwise 0.5. The general airborne path uses 0.1. The bitfields select the same words/masks as retail.
- **Timers and positional correction (`0x802BA254–0x802BA3A8`):** `_3AA` is decremented before converting its unsigned 16-bit result to float and dividing by 15. The formula weights the newly calculated offset by `1-rate` and the saved prior offset by `rate`, then sets turning. A nonzero `_334` is always decremented at the end. Its positional correction runs only for **vertical speed >160**, computes `_30C * 80 - mHeadVec * 80`, projects that difference onto `_240`, and calls `push2` with **positive** `_240 * projection`; only then is `_30C` updated to the current head vector.

This review checks source-level field/argument/sign/ordering correspondence, supplementing the author's compiler and control-flow evidence. It does not establish general native gravity or Mario jump execution, which remains outside this root-only restoration.
